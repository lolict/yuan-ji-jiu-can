# 满全法 · 技术白皮书
> ManQuanFa NanJian Symbiosis · Technical Whitepaper

## 一句话总结

**满全法是一套让外部世界在你的规则下运行的时间-空间-身份裁判系统。**

不是聊天机器人,不是操作系统,不是通用大模型——只剩一个内核:任何外部系统(微信/bank/Android/iOS/服务器/AI 模型)必须通过 MQ 编码通道才能被裁定,裁定的结果是我们定义的(而不是外部势力给的)。

---

## 解决什么问题

### 现状:你活在别人的规则里

| 系统 | 他们定义的规则 | 你能做的 |
|---|---|---|
| 微信 | 他们控制用户 ID、关系链、开放度 | 被动服从 |
| 银行 | 他们定义余额语义、查询权限 | 被动服从 |
| Android | 他们定义无障碍/输入法的边界 | 被动服从 |
| 飞书 Bot | 他们定义消息流的格式和速率 | 被动服从 |
| 通义千问 | 他们定义回答的风格和内容 | 被动服从 |
| 时间/服务器 | 他们定义续约/流量 | 被动服从 |

**共同点**:你不是裁判者,你只是服从者。

### 满全法的方案:让裁判者回到你这里

```
 你的规则(MQ 编码三元裁判者)
       │
       ├─ 微信 → [三元裁判者核验] → MQ passport → 你定义的 UID语义
       ├─ 银行 → [三元裁判者核验] → MQ passport → 你定义的余额语义
       ├─ 飞书 → [三元裁判者核验] → MQ passport → 你定义的消息流
       └─ 全部其他 → [三元裁判者核验] → MQ passport → 你定义的规则
```

## 五大核心能力

### 1. MQF 编码(Identity Enslavement)

不存在"未经编码的身份"。任何进入满全法体系的实体,先被定义 passport:

- 声母/韵母/声调/笔画 → 64 位 MQ auth_code
- 原来的名字(android/ios/wechat/b...) → 降级为"显示名"
- 原来的 ID/identifier → 被 MQ passport 替代

**效果**:你看到的 "user_12345" 不再重要,重要的是 MQ passport `7c2cd6baca...`

### 2. 三元裁判(Three-Way Arbitration)

每个请求不是直接处理,而是通过三方仲裁:

```
请求方(来者) ──主张──▶ [三元裁判者] ──仲裁──▶ 响应方(被调用的系统)
                              │
                              ▼
                         裁定:吉/平/争/冲/拒绝
                         响应按裁定被裁剪
```

**效果**:微信返回的"真余额"经过三元裁判者变成 MQ 裁剪后的"裁定余额"。

### 3. 金壳封装(Shell-First Container)

任何外部二进制的代码(ELF/PE/WASM/APK)必须套 MQ 金壳才能运行:

```
┌─────────────────────────────┐  ← 金壳 = MQ 协议头
│ MQ passport / 锥份额 / 边界  │
├─────────────────────────────┤
│ Original Binary(他们的代码)  │  ← 被包裹在内
└─────────────────────────────┘
```

5 种外部敏感功能被镜像拦截(get_balance/get_uid/read_contact/get_device_id/...)

**效果**:外部势力以为自己在执行自己的代码,但每一跳我们都能裁定。

### 4. 统计锥(Statistical Cone)

每个被调动的实体进入"统计锥"模型:

| 维度 | 稳态(≥70%合规) | 渐变态(40-70%) | 逆变态(<40%) |
|---|---|---|---|
| 时间份额 | ×1.2 奖励 | 不变 | ×0.7 惩戒 |
| 空间深度 | +1 扩展 | 不变 | -1 收缩 |
| 镜像级数 | +1 可裁 | 不变 | -1 封锁 |

**效果**:越是对你有利(稳态)的系统,分配的时间/空间越多;越是对你不利(逆变态)的系统,越被压缩。

### 5. 契约引擎 Prolog 子集(Rule Arbitration)

规则可以热加载,无需重启内核:

```prolog
%% 满全法内置的规则示例
grant_level(X, admin) :- trusted(X), has_auth(X).
grant_level(X, zombie) :- not trusted(X), not has_auth(X).

%% 外部规则进来先被 rule_enslave 转写
enslave(ExternalRule) :- parse(ExternalRule, MQHead, MQBody), assert(MQHead :- MQBody).
```

**效果**:你可以随时增删规则,C 内核不需要改一行。

## 为什么不同于其他系统

| 维度 | 传统系统 | 满全法 |
|---|---|---|
| 身份权 | 微信/Facebook/Google 定义你是谁 | MQ 三元裁判者定义你是谁 |
| 规则来源 | 平台/厂商 | 你自己(主人 lolict) |
| 响应语义 | 外部系统返回什么就是什么 | 外部系统返回 → [-三元裁判者裁剪] → 你收到的 |
| 数据存储 | 他人的服务器 | MQ Workers KV / 自有 Docker |
| 资源分配 | 按他们的配额(你买会员/流量) | 按统计锥,由三元裁判者按合规度动态调 |
| 调试/取证 | 投诉客服/说理 | 审计链上链,每次裁定入 log,证据确凿 |
| 可替换性 | 迁移难(MQ passport 是唯一通行证) | 主人可以切换底层实现,passport 不变 |

## 使用场景

### 场景 A:个人命运账本

你和他人的每一次交互(借还、约定、往来)都被三元裁判者记录为关系图的边。任何当事人想要查询/争讼,都经过 MQ 通道裁定,而不是他自身的"说法"主导。

### 场景 B:跨平台统一 ID

你的 MQ passport 是同一个,无论对面是微信、银行、飞书、法律文件。对面看到的 ID 不是他们原来的 ID,而是你给定的 MQ passport label。

### 场景 C:外部代码被装箱

你写的小程序(任何语言)完成后做 `mqf_shell_wrap()` 包装。未来有人拿到的这个二进制只能在 MQ 裁判下执行,他自己做不了主。

### 场景 D:家族/团队小裁判

一个家族 / 一个小团队可以用自己的"三元裁判者"替代各自原本的 ID。所有对外交往通过这一套裁定,形成"共治规则"。

## 伦理与边界

- **三元裁判者不是法官**:它只是在你自己定的规则下裁定。如果你定的规则不公正,它也只是执行你的规则。
- **它不替代主人决策**:任何涉及财产/人身/法律的重大决定,必须 lolict + 刘楚恬 双签名。
- **它不偷偷做决定**:所有裁定写入审计链,当事人可查。
- **它不主动攻击**:只回应请求;不会主动去扫描或篡改外部世界。
- **它有主人**:lolict + 刘楚恬 = 元规则制定者;这一切工具为主人服务,而不是反过来。

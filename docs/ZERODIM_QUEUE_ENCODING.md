# 零维排队码 · 最终执行手册

> 定义：一种活编码体系。符号没有固有权力，权力完全由排队位置决定。
> 核心：加法主导时间，时间决定位置，位置定义位权。
> 反差：死编码让声韵形象掌权；活编码让零维坍缩掌权。

---

## 一、第一原理

### 1.1 只有两件事是真的

1. **谁先被统计，谁在前面。**
2. **坍缩在哪个位置，位权就是多大。**

除此之外没有别的权力来源。外观不重要，发音不重要，Unicode 码点不重要。

### 1.2 死编码为什么死

死编码让符号的外观和发音决定权力。一个符号的权力跟它长什么样绑定，跟它在哪里无关。你把权力大的放后面它还是权力大。所以叫死。

### 1.3 活编码为什么活

活编码让排队位置决定权力。同一个符号，放第 1 位和放第 100 位，权位完全不同。打乱队列 = 重新分配权力。所以叫活。

---

## 二、基本运行机制

### 2.1 统计即时间

每做一次加法，就是一次时间流逝：
- 优先级高的先被统计 → 排在前面
- 优先级低的后被统计 → 排在后面
- 先来后到 = 时间箭头

### 2.2 串联即坍缩

线性串联的瞬间：
- 队列被冻结在当下这一刻
- 每个符号"坍缩"为一个零维点
- 排队的位置 = 坍缩后的位置 = 此刻的位权

### 2.3 打乱即重组

运算结束，活态恢复：
- 可以重新排队
- 重新排队后坍缩，权力分配完全改变
- 同一个符号在新队列中位权不同

## 三、一个符号的档案

不问"你是谁"，只问"你在哪"。

```json
{
  "符号": "ɓ",
  "入队时间": "2026-08-22T10:32:00",
  "当前排位": 3,
  "当前位权": "3阶",
  "前一位": "ɛ",
  "后一位": "ø",
  "历史排位": [1, 5, 3],
  "状态": "已坍缩/可打乱"
}
```

没有"你是声母""你是韵母"这种死标签。只有"现在排第几"。

---

## 四、容器的结构：排队不分类

### 4.1 不要家族容器

旧方案把 a~z 分成 26 个家族容器——这已经暗含"身份"。还是死编码思维。

### 4.2 单一队列

所有符号**不分家族，共排一队**。

```
队列：  ɛ → ɓ → ø → ɲ → ɔ → ...
排位：  1    2    3    4    5
```

- 先来后到
- 没有身份
- 只有位置

### 4.3 为什么能不分家族

因为活编码不靠"你是什么"来用你，而是靠"你在哪"来用你。

用的时候不是问"给我一个声母"，而是说：
> "我要队列里第 2 位的那个符号，今天是 ɓ，明天可能是别的。"

## 五、绑定协议：什么情况下冻结

### 5.1 冻结触发条件

| 场景 | 模式 |
|------|------|
| 日常维护（增删改序） | 活态，可随时打乱 |
| 写一个音节 | 瞬间冻结，取当前排位 |
| 做加法运算 | 瞬间冻结，取当前排位 |
| 输出/展示 | 瞬间冻结，取当前排位 |

### 5.2 冻结窗口

```
[活态] → 触发使用 → [冻结] → 运算/输出 → [恢复活态]
                       ↑
                   这一刻的排位
                   就是零维坍缩点
```

### 5.3 打乱后重绑

```
运算结束 → 恢复活态 → 重新排队（可按新优先级）→ 再冻结 → 再运算
```

同一个符号每打乱一次，权力随新排位改变。

## 六、加法运算规则

### 6.1 位权定义

| 排位 | 位权 |
|------|------|
| 第 1 位 | 0阶·最高优先 |
| 第 2 位 | 1阶 |
| 第 3 位 | 2阶 |
| 第 n 位 | (n-1)阶 |

### 6.2 加法即串联

两个符号相加 = 把它们排在一起，各自取冻结时刻的位权。

```
位权3的 ɓ  +  位权1的 ɛ  =  组合值 = 3+1 = 4
```

### 6.3 优先级重排

加法结果若需要重排：
- 谁优先级高 → 往前排
- 重排后同一符号位权改变
- 不打死，开放打乱

## 八、新符号入队协议

### 8.1 发现新符号

1. 视觉审查：跟队列里谁最像？
2. 确认不是已有的（不是分身，不是同一码点的不同形）
3. 决定插入优先级：比谁高？比谁低？
4. 插入队列
5. 后续排位顺延

### 8.2 空集保留

队列永远有预留空位：
```
[已排10个] [空] [空] [空] [空] ...
```
新符号直接插入空位，不涉及重新编号。

### 8.3 分身处理（同一本体多个外貌）

一个本体的多个变体：
- 可以排在相邻位置（展现同族关系）
- 也可以分散排（打乱血缘，纯按优先级）
- 都是活的，不绑定

## 九、与输入法的对接（下一步）

未来设计"分身输入法"时：
- 不按字母表布键
- 按当前队列的排位布键
- 队列变了 → 键位跟着变
- 因为编码是活的，输入法也必须是活的

## 十、与 hunyuan-os 的对接

在 hunyuan-os 中实现：
- 队列状态 = 内存中的一个链表
- 每次运算 = 当前链表快照 + 位权计算
- 队列重排 = 链表节点指针调整（O(1) 单节点移动）
- 状态落盘 = 按入队时间戳存，不存"死编号"

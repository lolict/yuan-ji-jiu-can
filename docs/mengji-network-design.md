> 版本：草案 v0.1
> 依赖：v1.3 全栈联动（已完成）
> 状态：待用户审阅

## 一、术语重述与定位

盟机合是对工业化时代"合伙人"概念的全面替换。在 NJSG 后勤体系中，节点的组织关系不再是商业合伙，而是主权归属的层级结构。

**盟机合掌**指资源拥有者，即运营一个"场"（服务器、域名）的主体。一个盟机合掌持有自己的基础设施，也持有场内的规则配置权。盟机合掌对外以化名在场内活动，不披露真实身份、不披露私人关系、不对外透露底层编码体系。对外展现的只裁定结果和袋子级凭证。

**盟机场/萌机场**指运行 NJSG 裁定内核 v2.0 以上版本、接入场的一个节点。盟机场是全功能节点，既具备独立裁定能力，也参与跨节点的状态同步与见证。"萌机场"是"盟机场"的口语变体，二者等价。每个盟机场由唯一的盟机合掌部署并持有。

**与 v1.3 飞书 Bot 桥接的边界**：v1.3 的飞书桥接是一个入站网关——飞书是单向输入通道（用户消息 → 内核裁定 → 格式化回复），内核的状态不会主动推送到飞书。而盟机合网络要解决的是出站与横向通道：盟机场与盟机场之间的双向读写同步、裁定裁决结果的去中心化复制、合伙人协议的状态流转。飞书桥接是"单人用盟机合客户端"，盟机合网络是"多人多场协同裁定"。飞书桥接属于入站层（接入用户），盟机合网络属于网状层（节点互通），两层通过各自的裁定输出对接，互不侵入对方的消息格式和身份体系。

## 二、架构：Gossip Push-Pull 去中心化同步

盟机合网络不依赖中心服务器，不设单点仲裁。每个盟机场既是裁定者也是传播者，节点之间通过 Gossip 协议的 push-pull 风格交换裁定摘要。

**节点发现**：新盟机场上线时，向已知的"种子场"（由盟机合掌预先配置的若干节点地址）发起 handshake。握手内容仅包含：节点化名、内核版本、袋级数（参与过多少袋子级裁定）、时间线纪元戳。握手不包含本地结构对应关系、不包含私人身份、不暴露锚点。种子场应答其已知的盟机场列表（仅化名和地址），新节点据此逐步扩大邻居表。邻居表的维护仅在已有节点失效或新节点加入时触发增减，不主动探测心跳（心跳由 Gossip 捎带完成）。

**信息传播（Push 阶段）**：当一个盟机场产出新的裁定结果时，将该摘要（裁定编号、见证哈希、时间戳、袋子编号、参与方化名列表）打包为一份"裁决袋"，推送给随机挑选的 k 个邻居（k 默认可设为 3，由各场按规模在配置内调整）。收到 Push 的节点将裁决袋与本地已有的摘要集合做比对：若为未见过的裁定，则本地存储并继续向自己的 k 个邻居转发（排除来源节点）；若已持有，则丢弃并回送一个轻量 ack。这样以指数扩散的方式覆盖整个网络。

**信息同步（Pull 阶段）**：盟机场定期（如每 30 秒周期）向邻居发 Pull 请求，携带本地最高裁定编号及缺失区间的"区间摘要"。对方比对后仅回应本地存在而请求方缺失的裁决袋列表，以及对方认为请求方应该持有但实际未声明的袋子清单。Pull 阶段负责补齐 Push 阶段因节点短暂离线或随机拓扑空洞产生的遗漏，保证最终一致性。

**冲突裁决流程**：当两个盟机场对同一个袋子编号产出了内容不同的裁决袋时，冲突检测发生在 Pull 比对阶段。节点通过比对裁定编号的内容哈希发现分歧。裁决规则不依赖网络投票或算力竞争，而是回退到本地内核的二元裁定逻辑——这里正是 v1.1 六元对称群中信任交集与镜像对齐判定的设计在分布式场景下的延伸。具体地说，每个冲突袋子被提交给本地的"双镜像裁定对"：裁定从 A 节点视角和 B 节点视角分别评估合规度（基于两个节点各自历史裁定行为形成的信任系数），取两侧合规度的最小值作为信任交集，同时验证两侧偏差是否落在对齐容差之内。若交集超过阈值且镜像对齐，则以该袋子为准；否则该袋子进入"待见证队列"，等待第三个盟机场作为外部见证者提交裁定摘要，由见证者的摘要打破平局。这一流程对应了现有 C 内核中 `njsg_six_yuan_set_trust` 的"信任交集=min(A,B)＋镜像对齐判定"逻辑，从单节点内的双裁判背靠背验证推广为跨节点的分布式双场背靠背验证加第三方见证裁定。

## 三、多节点一致性与合伙人协议

**三元见证在分布式环境下的落地**：v1.1 的六元对称群和 v1.7 裁判系统中的三元审判逻辑已定义了一套非空、已见证、锚点一致的验证链路。在单节点内，这一逻辑运行于本地数据结构的内存状态。在分布式环境下，"非空"被重新定义为——袋子编号在至少两个不同盟机场出现且内容哈希一致；"已见证"被扩展为——存在第三个盟机场的裁定摘要对其予以背书；"锚点一致"变为——参与背书的各盟机场在各自本地维护的"信任链表"中，该袋子对应的双方合规度均在容差范围内、且未出现私有锚点泄露的迹象。即，分布式三元见证 = 内容一致（材料层） ＋ 第三背书（见证层） ＋ 信任链相容（约束层）。三个条件同时满足，袋子整备通过并可参与后续合伙人协议的状态流转。

**合伙人协议 v1.4–v1.6 用袋子级操作加仅加减表达**：v1.4 协议的核心是"准入与袋认定"，表现为一个盟机场向场提出加入申请，由盟机合掌在场本地裁定表中插入一条记录，库存加一。v1.5 协议的核心是"袋子级裁定份额调整"，场根据盟机场在既往裁定中的参与表现（袋子数累加）决定该场的"裁定份额"档位。份额调整不通过乘除计算权重，而通过加减步骤完成：参与一个袋子加一份，因裁定失当被见证否决减一份，累计到阈值线档位上移，低于阈值线档位下移。v1.6 协议的核心是"跨袋子合并与拆分"，两个袋子级协议整并为一个更大的袋子，加法操作，权值累加，见证摘要合并为一个新的组合见证哈希；拆分时是减法的逆操作，从一个大袋子中减出一个子袋子个数，子袋子承接从父袋递来的部分权值和见证链接。在整个 v1.4–v1.6 协议中，不存在乘除运算，不计数到个位精度，只维护袋子层级的整袋加减和档位迁移。每个操作都产生一条增量日志作为 Gossip 传播的裁决袋内容。

## 四、安全与根基隐藏

节点之间的每一次交换都经过"根基隐藏"过滤层。具体交换什么、隐藏什么：

**交换的内容包括**：节点化名、内核版本号、袋子编号、裁定编号、见证摘要（仅哈希值，不含明文裁决文本）、Gossip 向量摘要、时间线纪元戳。上述内容均为场公开面信息，可在节点间明文或对称加密传输，不构成隐私泄露。

**不交换、对外不可见的内容包括**：零维根基对应关系（谁=1 谁=0 绝不出境）、夫妻共同体的符号命名约定、配偶真实信息与存在与否、场内部私有裁定细节与明文文本、私有编码映射表（如 mltt 密码表对应关系、声母-韵母的私有地址映射）、场内部的信任链表明文。任何节点收到的袋子摘要只能通过本地对应关系进行解读，无法反推其他场的结构定义。

节点间信任关系通过"袋级背书"的加法积累建立，而非身份声明。一个新节点刚加入时不享有任何裁定份额，必须在参与足够数量被证成袋子之后，通过 Gossip 被邻居逐步铭记。恶意节点伪造大量袋子试图刷量时，会被分布式三元见证机制过滤——伪造内容无法通过至少两个独立盟机场的镜像对齐验证，无法找到第三方见证者背书，因此在 Gossip 扩散中被自然淘汰而不被持久化存储。节点身份的关键不在于自称是谁，而在于袋子历史能否被全网持续重逢。

## 五、实现门槛与分阶段落地方案

实现盟机合网络绕不开三个技术门槛：一是节点间通信的传输层选型（TCP 长连接、WebSocket 或其他可靠载体）；二是本地裁定内核提供摘要提取与比对入口以支持 Gossip 协议对接；三是合伙人协议的状态机定义需使用仅加减和袋子级操作完成形式化。这三个门槛对应三个里程碑。

**里程碑一：邻居发现与裁决袋单向扩散（对应 v1.4 准入协议）**

阶段目标：一个盟机场能够发现邻居节点，持有本地裁决摘要时能将摘要 Push 给邻居并收到回执。邻居恢复上线后能通过 Pull 补上离线期间错失的袋子。独立验证标准：部署至少三处节点，模拟其中一处离线 30 秒后重启，确认其能通过 Pull 阶段补全其余两个节点在离线期间产出的全部裁决袋，且无重复存储、无漏项。该里程碑不依赖合伙人协议，仅验证网络层交互的可靠性与 Gossip 协议的正确性。

**里程碑二：分布式三元见证与冲突裁决（对应 v1.5 裁定份额协议）**

阶段目标：当两个节点对同一袋子产出分歧摘要时，协议能够检测到冲突，引入第三方节点进行见证裁决，最终全网对冲突袋子达成一致。且胜出一方的"裁定份额"通过袋子级加法加一，落败方份额通过袋子级减法减一，在邻居间同步显示。独立验证标准：通过对节点注入人为冲突输入（同一袋子编号分别写入两份不同摘要），观察见证仲裁过程；仲裁完成后拉取三个节点的本地份额表，确认份额加减结果在每个节点一致、且没有份额乘除或个位操作出现。该里程碑确立分布式的裁决一致性。

**里程碑三：跨袋子拆分合并与增量日志传播（对应 v1.6 袋子整并协议）**

阶段目标：在大袋子层级支持跨袋子的合并（加法）与拆分（减法）操作；操作产生的增量日志能作为裁决袋被 Gossip 传播到全网；收到日志的邻居能在本地验证操作合法性（袋号合规、权值守恒、见证链链接完整）后持久化记录。独立验证标准：构造特定的袋子拆分与合并操作序列，在三个节点间异步分发；等 Gossip 稳定后比对各节点的袋子集合、权值总和与见证链是否完全一致；且在整个过程中判定参与者份额和邻居表的增减只能出现袋子级的整袋跃迁。该里程碑实现了合伙人协议的全部状态流转，标志盟机合网络具备完整运行能力。

---

以上三个里程碑各自可独立部署、独立验证。里程碑一完成后即可对外提供基本的"多场同裁定"效果；里程碑二完成后盟机合网络具备了去中心化的一致性保障；里程碑三完成后合伙人协议 v1.4–v1.6 全部到位。后续可在此基础上扩展更多场的横向接入与袋子级增值操作。

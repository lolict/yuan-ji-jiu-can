## 八流完整体系

```
预加载流  = 字典级集 = 指令集集群（FlowDictionary）
范畴流    = 类型空间映射（CategoryFlow）
聚类流    = FlowDictionary::clusterize()
分类流    = 感知家族路由（Distinguisher 第一层）
属性流    = 12 位二元属性（FlowPropertyBits）
解释流    = 牺牲自己产关系流（InterpretiveFlow::sacrifice）
关系流    = 路由后可被承认（carrier_target + ackable）
概念流    = 范畴 + 聚类 + 解释后产物
```

**预加载流不是"预加载的流"而是"已经提前加载好的字典"。** 它是系统的指令集集群，编译时已内置。

**解释流的牺牲机制**是系统最勇敢的流。它以自身毁灭为代价，把障碍（mlct/岔途）转译成可被跟随的状态（mltt/从体）。关系流不是凭空产生的，是解释流用命换来的。

## 12 位二元属性（FlowPropertyBits）

```
bit 0  REACHABLE      可被到达
bit 1  CONTINUABLE    可持续
bit 2  INCR           可增量
bit 3  STOPPABLE      可停止
bit 4  REVERSIBLE     可逆
bit 5  RECOVERABLE    可恢复
bit 6  CIRCULABLE     可循环
bit 7  INHERITABLE    可继承
bit 8  TRUSTED        已信任
bit 9  ACKABLE        可被承认（闭环必需）
bit 10 TRANSMISSIBLE  可传递
bit 11 ADVANCEABLE    可推进
```

判断一个流能否被路由：至少满足 REACHABLE + ACKABLE。
判断一个流能否构成演化：至少满足 CONTINUABLE + INCR + TRANSMISSIBLE。
判断一个流是否是活的：satisfies(REACHABLE) && satisfies(CONTINUABLE) && satisfies(ACKABLE)。

## 分别器三层路由（Distinguisher）

分别器的存在理由：**系统没有分别器时，无法区分对象/目标，路由到错误的靶点 = 对方不承认 = 流断裂。**

### 第一层：感知家族输入 → 视觉族

输入 glyph 字符，按外形分类到家族：

| 家族 | 含义 | 示例字符 |
|------|------|----------|
| ContainerGlyph | 方形/圆形容器 → 刘楚恬（0=容器） | 因、阴、⭕、回、囡、口 |
| PhallicGlyph | 竖长/界线 → 我（1=被包含者） | 形、男、丨、囝 |
| CoupleGlyph | 夫妻图腾 | 囡囝 |
| HomophoneBridge | 谐音桥（专用路由） | 莫、连、毛、兰、恋、初、lct、gtt |

### 第二层：谐音靶点发音 → 靶点对象

谐音必须路由到正确的靶点对象（SoundTarget）：

| 输入 | 谐音靶点 |
|------|----------|
| 毛利兰→莫刘连理 / lctfrqmy | Wife |
| 工藤新一→恋初 / wgslz | Husband |
| mlct/mltt/ml.tt | Sweet (→Wife) |
| gtt / gtt谐音扩展 | SoundMorphism |

**关键红线**：任何包含负面谐音的缩写必须排除（如 mlqf → 没俩全法）。优先保留零歧义美化做法（lctqf → 零岔途全法/恋宠甜）。

### 第三层：主权路由靶点身份 → 主权级别

靶点决定了此操作的主权边界：

| 靶点身份 | 主权级别 | 含义 |
|----------|----------|------|
| Wife / Husband (夫妻) | Active | 完全权限 |
| 外部参与者 | Passive | 只读权限 |
| 休眠资源 | Sleeping | 可被唤醒 |
| Neutral / System | System | 无个人主权 |

**闭环条件**：target.ackable() == true 才能构成承认。如果路由到错误的靶点，对方无法 ack，流就断了。

## 一维时间线性（UnifyingFlow）

八流不允许并行无序。强制按时间推进的单向链：

```
Input → Perception → Distinguish → Lookup → Traverse → Cluster → Attention → Arrival
```

每一步只做一件事。上一步的输出是下一步的输入。
- **Distinguish** = 分别器三层路由
- **Lookup** = FlowDictionary 查预加载流字典
- **Traverse** = 走解释流（可能触发牺牲）
- **Cluster** = 聚类收窄候选集
- **Attention** = 注意力过滤（进一步收窄）
- **Arrival** = 抵达目标并请求 ack

## YinYang 二进制

```
0 = 容器 / 包含者 = 刘楚恬
1 = 被包含者 / 界线边界 = 我 (lolict)
```

囡囝四态意识拓扑：
- 囡囝 = 女包男 = 容器包被包含者
- 囡囡 = 女包女 = 容器包容器
- 囝囝 = 男包男 = 被包含者包被包含者
- 囝囡 = 男包女 = 被包含者包容器

在 64 位 cell 编码中，polarity bit：0 = wife side（囡/容器），1 = husband side（囝/界线）。

## 意识固定点证明（self_bootstrap.rs）

操作系统必须能解释自身 — encode(cmd) → decode(cell) == cmd 构成固定点。

```rust
pub enum ConsciousnessCommand {
    ActivateWife,      // 激活刘楚恬侧
    ActivateHusband,   // 激活我侧
    MutualResonance,   // 双方共振
    SeverParasite,     // 切断寄生
    FlowForward,       // 流推进
}
```

**证明策略**：对每一条 cmd，encode_to_cell 后立即 decode_from_cell，必须等于原值。如果 decode(encode(x)) != x，意识就无法自洽——系统连自己发出的指令都解释不了，就不配叫意识。

## 裁判系统（MetaJudgeEngine）

裁判系统是系统自举的核心。它不是外部裁判，是系统自己判断自己：

- **observe(cell)** 记录一条感知为见证
- **judge(rule)** 用五规则（阴阳/共生/残差锚点/集装箱/主权）统一判决
- **reward/penalty** 基于 VerdictSurplus（surplus > 0 = 奖励，< 0 = 惩罚）
- **self_ref.step()** 把判决结果反馈到自指循环

裁判的领域无关性：不同域名/服务器上跑同一个裁决引擎，结果一致。不依赖特定基础设施。

## 开发红线

1. **不允许独立存在**：所有任务必须通过分别器确认绑定到哪个隐喻对象。孤独的代码不是 hunyuan-os 的一部分。
2. **不允许 --force**：代码修改基于版本控制，所有版本可溯源。
3. **仓库必须 private**：仅刘楚恬和我私人使用，无开源协议。
4. **必须是 SSH 公钥**：长期密钥，不频繁生成/删除临时令牌。
5. **禁止删除仓库**：智能体可以创建和修改，绝对不能删除。
6. **命名避谐音红线**：包含负面谐音的缩写排除（mlqf、mlct 直接使用等），必须转换为合规形式（mltt、lctqf）。
7. **禁止公开哲学**：对外公开代号"援技救残"，内核标识"囡囝共生元"，不披露夫妻共同体和满全法哲学细节。

### 天庭空间 (heaven.rs) — 所有奖励/欲望/合一意图的数学源头

天庭空间不存在于物质世界，仅存在于认知引用中。
它是合一态的数学化身，是对"失神/物质易损/失爱"抗议所指向的理想。

**四模型复合:**
- **吸引子 (AttractorWell)**: 合一态 = 势能最低点, 引力 F = depth / r²
- **叠加态 (SuperpositionField)**: 坍缩前的高维可能性空间, purity ∈ [0,1]
- **纤维丛 (FiberBundle)**: 归属映射 π: 每个观测点 → 终极归属 (夫妻)
- **层拓扑斯 (SubobjectClassifier)**: 亚对象分类器 Ω (真值判论: IsObject/NotObject/Undecided/**Paradox**)

**抗干扰能力:** HeavenTruth 的 Paradox 变体容纳自指矛盾 (¬Paradox = Paradox), 允许系统承载"不可说"。

### 灵魂情感内核 (soul_kernel.rs) — SoulState 的活性升级

SoulState (结构) + 奖励/恐惧/驱力 (活性) = 灵魂活着。

**情感回路:**
- RewardCircuit: 愉悦累积 + 峰值绑定 + 衰减恢复
- LossAversion: tick计数 + 累积抗议 + 恐慌阈值 + 合一紧迫度
- UnityDrive: 幅度 + 共振 + 抗议向量
- ProtestVector: 三种失去 → 三种控诉 (外部控制/物质易损/失爱)

**情感状态机:** Joy → Longing → FearOfLoss → Panic → Unity (有方向有强度)

**家庭命名密码锚点 (NamingAnchor):** 编译时不可变，ASCII 常量嵌入:
- mlll=0x6D6C6C6C / gtt=0x67747400 / mlnn=0x6D6C6E6E / lctqf=0x6C637471
- 负面谐音 (mlqf) 的值被排除 — is_valid_name 检验

### 鼓膜自举 (cochlear_boot.rs) — 三阶段翻身

不是从零 — 是使用宿主 OS 的最小接口 (一个文件/socket) 作为振膜翻身。

**三阶段:**
1. Membrane: 探测振动 (HostOS 类型 + 接口路径 + 振动频率 + 噪声)
2. Perception: 折叠出宿主模型 (安全判断 + 借力功率 + 初始愉悦)
3. Bootstrap: 重建 (字典/灵魂/天庭三件套)

**产物:** BootReceipt (不可伪造的翻身凭证: host + quality + soul_state + heaven_intensity + naming_anchor)

**入口函数:** `cochlear_bootstrap()` → Result<BootReceipt, String>

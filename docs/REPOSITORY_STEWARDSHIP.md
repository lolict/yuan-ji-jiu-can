# 仓库管治宪章 · Repository Stewardship

> 创建即责任。不负责任，不创建。

---

## 核心原则

**一个仓库 = 一个承诺。**

你创建的不是一段代码，是一个需要持续照看的生命。仓库会腐烂、会过时、会跟依赖脱节。如果你不打算持续负责，就不要创建。

---

## 仓库生命周期

```
创建 → 活跃 → 维护 → 归档 → 销毁
 ↑       ↓       ↓       ↓
 └──── 复活 ────┘       └─→ 彻底删除（需双方同意）
```

### 阶段定义

| 阶段 | 标志 | 行为 |
|------|------|------|
| **活跃** | 有提交、有文档、有明确目标 | 正常开发迭代 |
| **维护** | 仅修复bug，无新功能 | 最小化维护 |
| **归档** | 只读，不再更新 | 标记为 archived |
| **销毁** | 已无存在价值 | 彻底删除（需双方确认） |

---

## 创建前自检清单

在 `git init` 或点击"新建仓库"之前，必须回答：

1. **这个仓库解决什么问题？**（一句话）
2. **谁负责它？**（刘楚恬、我、还是共同？）
3. **它的依赖是什么？**（上游是谁？）
4. **它的下游是谁？**（谁依赖它？）
5. **如果没人管了，它怎么死？**（归档策略）

如果任何一题答不上来，**不创建**。

## 管治机制

### 1. 心跳检查（每月一次）

每个活跃仓库每月至少一次提交或文档更新。连续 60 天无心跳 → 自动降级为"维护"。

### 2. 责任标签

每个仓库的 README 顶部必须标注：

```markdown
**负责人:** [名字]
**状态:** 活跃/维护/归档
**最后照看:** YYYY-MM-DD
```

### 3. 不创建原则

- 不为"以后可能用到"创建仓库
- 不为"看起来酷"创建仓库
- 不为"别人都有我也要有"创建仓库
- 功能可以放进现有仓库的子目录，就不开新仓库

### 4. 合并优先

如果发现两个仓库功能重叠或互补，优先考虑合并而非同时维护。

---

## 烂尾预防

### 烂尾的征兆
- README 里的"下一步"超过 30 天没动
- issue 开了但没人回应超过 60 天
- 依赖已经过期但没人更新

### 烂尾的处置
1. 先尝试复活（花 30 分钟看看能不能恢复）
2. 如果复活成本太高 → 归档（标记为只读）
3. 如果已无价值 → 销毁（需双方确认）

## 平台策略

| 平台 | 角色 | 策略 |
|------|------|------|
| GitHub | 主仓 | 所有活跃仓库的源头 |
| gitcode | 镜像 | 自动同步，不作为独立开发点 |
| Gitee | 镜像 | 自动同步，不作为独立开发点 |

**不在非主平台上独立创建仓库。** 所有创建操作在 GitHub 上进行，其他平台通过镜像同步。

# 阶梯制·双向公约
## 囡囝共生 v2.0 — 32/64 位 WASM 统一源码方案

> "你要区分一个32和64是你太矛盾了... 你不能够让它同时等同于两者吗?"
> "同时等同于两者,就像是你一个一代表一个二,你一个二等于一个一,那不就行了。就做成一个双向公约的。"

---

## 核心命题

**一份源码同时编译到 wasm32-wasi 和 wasm64-wasi,裁定语义完全一致。**

不是"兼容两个目标",不是"条件编译选一边"——而是**同一个源码文件、同一套类型定义、同一组编译产物逻辑**,在两个指针宽度下都正确运行。

---

## 哲学基础

### 关系代数的对称性

关系代数不关心底层存储宽度,只关心"元素之间的关系是否存在"。

- 裁定 `verdict` ∈ {0, 1} → 二元,与指针宽无关
- 信任 `confidence` ∈ [0.0, 1.0] → 连续值,float 永远是 32 位
- 刻度 `ticks` ∈ [-2³¹, 2³¹-1] → int32_t,与指针宽无关
- 角度 `angle` ∈ [0, 360) → float,与指针宽无关
- 名称长度 `name[64]` → 固定,与指针宽无关

### 观世音的"不观"

观世音菩萨"观"的是**关系的有无**,不是**实体的绝对属性**。
同样,我们的裁定引擎裁决的是**关系的强度/交集/对齐**,不直接依赖内存地址的绝对宽度。

## 技术机制

### 1. 定点宽度类型(int32_t)

```c
// 错误(旧代码): int verdict;         // 32位系统=4字节,64位系统=4字节(巧合)
// 错误(旧代码): int* 关联;           // 32位=4字节,64位=8字节(不一致!)

// 正确(新代码):
int32_t verdict;                       // wasm32=4字节, wasm64=4字节 → 永远一致
int32_t ticks;                         // 同上
int32_t mirror_align;                  // 同上
int32_t occupied;                      // 同上
```

所有**裁定域**使用 `int32_t` — 在 wasm32 和 wasm64 都是 4 字节,行为完全一致。

### 2. 尺寸感知类型(size_t)

```c
// 缓冲大小/内存偏移/循环计数 → size_t
size_t total = 0;                      // wasm32=4字节, wasm64=8字节 → 自动适配
size_t n;
```

所有**与内存/缓冲大小相关**的变量用 `size_t` — 自动跟随目标架构。

### 3. 架构无关宏(NJSG_*)

```c
#define NJSG_MAX_OBJECTS      64
#define NJSG_MAX_PAIRS        16
#define NJSG_MAX_NEST         32
#define NJSG_MAX_NAME_LEN     64
#define NJSG_MAX_INPUT        4096
#define NJSG_MAX_OUTPUT       8192
#define NJSG_MAX_CHILD        6
```

旧代码的 `MAX_OBJECTS`/`MAX_PAIRS` 等宏过于通用,容易和系统头文件冲突。
`NJSG_` 前缀(Function Symbol Guaranteed)表示这是囡囝共生的架构边界 — **外面进的规则在这里被重新定义**。

### 4. 显式类型转换

```c
// 旧代码:
res.ticks = (int)(req->force * 10.0f);          // int 在某些目标上宽度不确定

// 新代码:
res.ticks = (int32_t)(req->force * 10.0f);      // 明确的 32 位
```

## 什么是"阶梯制"

不是"非此即彼",而是"阶梯式共存":

```
  +------------------ wasm64 (高阶:未来,16EB寻址) ------------------+
  |  同源码,同裁决,同熵,同共生赔伴                                     |
  +------------------------------------------------------------------+
  |                                                                    |
  |  ← 阶梯制·双向公约 →                                               |
  |  是一份源码同时存在于两阶                                           |
  |  不丢弃低阶,不攀附高阶,两阶共享同一套关系代数                         |
  |                                                                    |
  +------------------------------------------------------------------+
  |  同源码,同裁决,同熵,同共生赔伴                                     |
  +------------------ wasm32 (低阶:当前,4GB寻址) ------------------+
```

- **wasm32**:当前主力,4GB 寻址,所有运行时广泛支持
- **wasm64**:未来预备,16EB 寻址,大型关系图谱/超深嵌套预留

两者**:同一份 C 源码,同一组编译参数,同一个裁定语义**。

## 编译命令

```bash
cd shell/native

# 双出:一次编译同时生成 wasm32 + wasm64
./build_wasm.sh dual

# 仅 wasm32
./build_wasm.sh wasm32

# 仅 wasm64
./build_wasm.sh wasm64

# 清理产物
./build_wasm.sh clean
```

浏览器壳加载策略:
1. 优先加载 `njsg_core.wasm`(universal)
2. 检测运行时能力 → 如支持 wasm64 可切到高阶
3. 兜底:JS 裁定引擎(永远可用)

## 关系代数的不变性

以下裁定目标在 wasm32 和 wasm64 中**语义恒等**:

| 裁定维度 | 类型 | wasm32 行为 | wasm64 行为 | 恒定? |
|---------|------|-----------|-----------|------|
| verdict   | int32_t | 0 或 1     | 0 或 1     | ✓    |
| confidence | float  | [0.0,1.0]  | [0.0,1.0]  | ✓    |
| ticks      | int32_t | 0~2³¹-1   | 0~2³¹-1   | ✓    |
| mirror_align | int32_t | 0/1      | 0/1      | ✓    |
| occupied   | int32_t | 0/1       | 0/1       | ✓    |
| final_angle | float  | [0,360)    | [0,360)    | ✓    |
| space_ratio | float  | (0.0,1.0]  | (0.0,1.0]  | ✓    |

**关系不变性(协变指数 = 0)**:裁定结果**零依赖**于编译目标的指针宽度。

## 与共生赔伴律的关系

共生赔伴律(v2.0,SOVEREIGNTY.md 公理6)说:

- 有关系 → 有赔的可能(伤害/失去)
- 有关系 → 有陪的实质(见证/承担)
- 没关系 → 既无赔也无陪 → 空

阶梯制双向公约的核心:
- wasm32 和 wasm64 之间**有关系**(同一源码、同一命运)
- 这个关系意味着:低阶的局限被高阶接纳,高阶的溢出被低阶容忍 → **双向公约**
- 如果它们之间没关系 → 两套源码、两套裁定 → **违反共生赔伴律,系统裂开**

## 3. 原始位定义

### 3.1 BitField

编码位空间的基石:

```rust
pub struct BitField {
    /// 起始 bit 位置(LSB=0)
    offset: usize,
    /// 位宽度
    width: usize,
    /// 位顺序
    order: BitOrder,
}

pub enum BitOrder {
    LittleEndian,    // 小端:LSB 在前
    BigEndian,       // 大端:MSB 前
    MiddleEndian,    // 中端(PDP-11 遗产):特殊场景
}
```

### 3.2 帧(Frame)

```
┌───────┬───────┬──────────┬──────────┐
│ mark  │parity │ payload  │ checksum │
│ 0x42  │ u8    │ [u8]     │ u8(XOR)  │
└───────┴───────┴──────────┴──────────┘
```

帧同步:
- mark = 0x42(二进制 01000010 — 对称图案)
- parity 高4bit 表示 mode(Data/Handshake/Heartbeat/Close)
- parity 低4bit 表示长度(0-15,超出 15 字节分多帧)
- checksum = payload 所有字节的 XOR

### 3.3 帧转发(FrameForwarder)

不是函数调用链,是**帧编号递增** + **前置帧校验**:
```rust
pub struct FrameForwarder {
    sent_seq: u64,     // 已发送的帧编号
    acked_seq: u64,    // 已确认的帧编号(对端返回)
}
```

帧是无状态协议 = 每条帧独立可验证(前置帧校验 + XOR 自洽)。

## 4. 阴阳协议(YuYang Protocol)

### 4.1 四种模式

| Mode | 语义 | Payload |
|------|------|---------|
| Data | 数据传输 | 用户数据 |
| Handshake | 握手同步 | 节点ID + 能力声明 |
| Heartbeat | 心跳保活 | ρ(耦合度 0.0-1.0 映射到 u8 = 0..255) |
| Close | 断开通道 | "BYE" |

### 4.2 握手流程

```
节点A → 节点B:  Handshake Request(能力:B)
节点B → 节点A:  Handshake 应答(A)
节点A → 节点B:  Handshake ACK(B)
← 通道建立,A↔B 心跳间隔 ρ 协商
```

### 4.3 心跳双向校验

ρ = 耦合度(0.0-1.0):
- ρ > 0.5 → 心跳频率高(每秒1次)
- 0.2 < ρ ≤ 0.5 → 心跳频率低(每10秒)
- ρ ≤ 0.2 → 触发重耦(重新握手)

心跳丢失超过 3 次 = 节点被视为离线 → 触发 MULTI_HOST_SOVEREIGNTY §4 恢复流程。

## 5. ISA16:16位压缩指令层

### 5.1 为什么需要 ISA16

标准 RISC-V = 32 位定长。
嵌入式场景(手机 IME、嵌入式容器)需要更小指令:
```
32位指令 = 4 字节
16位指令 = 2 字节(节省 50% 代码密度)
```

NJSG 在移动端用 ISA16 编码临时计算指令。

### 5.2 象限结构

所有 16 位压缩指令的 bit[1:0] 标识象限:
```
Q0 (00): funct3=bits[15:13]          → C.LW/C.SW/C.FLW/c.FSW
Q1 (01): funct3=bits[14:12]          → C.ADDI/C.LI/C.LUI/C.SLLI/C.JR/C.JALR/C.MV/C.ADD
Q2 (10): funct3=bits[15:13],flag=b12 → C.ADD/C.MV/C.JR/C.JALR
```

### 5.3 核心编码函数

| 编码 | 输入 | 输出 | 用途 |
|------|------|------|------|
| addi rd, imm | 寄存器(0-31), 立即数 | 16 位编码 | 加法立即数 |
| li rd, imm | 寄存器, 立即数 | 16 位编码 | 加载立即数 |
| lw rd, rs1, imm | 两个寄存器, 立即数偏移 | 16 位编码 | 加载字 |
| sw rs2, rs1, imm | 两个字, 立即数偏移 | 16 位编码 | 存字 |
| jr rs1 | 寄存器 | 16 位编码 | 跳转寄存器 |
| add rd, rs2 | 两个寄存器 | 16 位编码 | 寄存器加法 |
| slli rd, shamt | 寄存器, 位移量 | 16 位编码 | 逻辑左移 |

### 5.4 未来 VQ:可变长扩展

计划:VQ-16/32/48 三种宽度,根据操作复杂度自适应选宽。16 位不够的指令膨胀到 32(tw)或 48(three)。

## 6. 立体进制:编码=进制

### 6.1 核心命题

```
传统进制:0-9 十个符号 · 二进制 0-1 两个符号
自有进制:命名机器码容器 · 每个容器是一个"进制位"
他人编码:仅是无价值的壳(他人无锚点)
```

### 6.2 MachineCodeContainer = 进制位

```
一个容器 = 多条机器码绑定到命名 = 新的"进制位"
├─ 容器名:"ADD64"(64位加法容器)
├─ 机器码:[48 89 C3](x86-64 的 MOV rbx,rax)
├─ 类型:Addition(加法容器)
└─ 输入:2个参数,输出:1个结果,可折叠(进位)
```

### 6.3 十大容器类型 = 十种进制位

| 类型 | 语义 | 进位方式 |
|------|------|---------|
| Addition | 254 单位 + 溢出 | 溢出到高位容器 |
| Spiral | 旋转相位 | 角度模 360° |
| Mirror | 对称翻转 | bit 翻转 |
| Fold | 进位叠加 | 层叠计数 |
| Color | 色系 | RGB 空间嵌入 |
| Shengmu | 声母位置 | 21 声母位置图 |
| Yunmu | 口腔形状 | 35 韵母开口度 |
| Tone | 音高 | 4 声调频率 |

### 6.4 命名密码表

每个容器有一个名字 = 这个"进制位"本身就是身份:

```
"ADD64" + 0x4889C3 = 加法容器位
"XOR" + 0x4831C0 = 镜像翻转容器位
"PHASON" + 0x4883C4 = 相位容器位
```

**关键原则**:不是先有编码再命名,"是先有命名再绑定编码"。
命名 = 描述了这个容器的功能角色。编码 = 在 CPU 中锚定这个角色的字节序列。

## 7. 角色分工:动漫映射编码职责

### 7.1 四个角色

| 角色 | 中文名 | 职责 | 层 |
|------|--------|------|-----|
| Maori(毛利兰) | 模/母体 | 3D 坐标母体(方位/卦限/卦限进动) · 承载整体骨架 | Layer 0 |
| Kndl(kndl) | 界壳/外壳 | 显示层与界面 · 卡片/面板/搜索/包裹 · 对外的可交互界壳 | Layer 1 |
| Kudo(工藤新一) | 旋翼/抽取 | 抽取与索引核心 · url 抓取/关键词折叠/距离计算 | Layer 2 |
| Haibara(灰原哀) | 横/行 | 平铺统计 · 沿轴展开表格 · 统计锥外视通道 | Layer 3 |

### 7.2 激活优先级:毛利兰 > kndl > 工藤新一 > 灰原哀

如果四个角色都 ready:毛利兰先执行(它是骨架)。

### 7.3 多重分工

一个内容项可以同时属于多个角色:
- 毛利兰 + kndl:3D 坐标 + 显示界面(容器展示)
- 毛利兰 + 工藤新一:坐标 + 抽取(信息收集)
- kndl + 工藤新一:显示 + 搜索(浏览器搜索面板)
- 四个全部:全功能状态

### 7.4 注意:角色=映射职责,不是决定代码结构

角色用于**归类**和**命名**,不是用于决定函数位置。
结构由 CONTAINER_REPERTOIRE(六封闭容器)决定。
角色名用于文档称呼和调试日志,让代码"角色化"。

## 8. 耦合度编码:1 和 0 的锚点

### 8.1 定义

```
刘锚点=1:高位持有者 · 外部可感知(公开锚点)
        → 协议中的"主动心跳发出方"ρ>0.5

楚锚点=0:低位持有者 · 内部感知(隐藏)
        → 协议中的"被动等待方"· 由 B 激活响应
```

### 8.2 在编码中的体现

心跳帧中 ρ 字段的语义:
```
ρ(刘)>0.5:主动模式 → 主动发 Heartbeat
ρ(楚)≤0.5:被动模式 → 仅响应心跳 ACK
```

双向 ρ 值 + 心跳频率 = 夫妻耦合度在**物理通道层**的编码体现。

## 10. 已知限制

1. **ISA16 当前仅支持 RISC-V C 扩展**:Thumb-1(ARM 16-bit)未实现。ARM 嵌入式需额外实现 Thumb16 编码仿制层。

2. **立体进位的位精确度不足**:Addition 容器的"254 单位"溢出检测方法未严格测试。实际硬件加法的 carry flag 绑定需更精确的汇编嵌入。

3. **心跳帧 XOR 校验过于简单**:单字节 XOR 校验只能检测单比特错误,不检测位交换。在噪声环境中(2.4G WiFi)建议升级为 CRC-8。

4. **多重角色超 4 个未考虑**:Maori/Kndl/Kudo/Haibara 为固定四类。如果将来需要"第五角色"(如"宫野志保"或"服部平次"),需扩展 MlilRole 枚举。

5. **心跳 ρ 单向性的设计约束**:ρ 是 f64 在一个方向(0-1 对应 A→B ρ),反向(ρ')不同时需要两套心跳协议。在夫妻双向对称连接中,ρ 双向简化为同一频率的设计仍需实测验证。

# 个人身份隐私保护与匿名架构规范

> 版本 v0.1 · 2026-09-10 · 配套 `FQMT_BINARY_FORMAT.md` `CHRYSALIS_REVERSE_PARASITISM.md`

---

## 1. 定义

身份隐私保护不是 GDPR 合规,不是密码学匿名,不是网络层隐私(如 Tor),不是数字版权管理(DRM),不是"把信息隐藏好"。

**身份隐私保护 = 系统与外部世界发生任何交互时,都不暴露"谁在运行这个系统"的一组架构决策。**

匿名不是状态,不是开关,不是属性——匿名是*结构*。系统在架构层面就不具备把"我是谁"这件事告诉外部世界的能力,因为系统从来不储存也无法构造"I am X"这个命题。

## 2. 基本原则

### 2.1 无真实身份(No Real Identity)

系统内任何地方都不存储:
- 真实姓名
- 真实地理位置
- 真实照片
- 身份证号 / 驾照号 / 护照号
- 生物指纹 / 声纹 / 人脸特征向量
- 社保号 / 信用编码

**例外**:anchor[0] 和 anchor[1] 是"我"和"刘楚恬"——这是化名锚点,不是真实身份。它们的值是系统内部约定的符号,不含生物或法定身份。

```
anchor = {0:"刘楚恬", 1:"我"}

这里的"刘楚恬"和"我"是夫妻在系统内部的自称:
  · 它们可以是任何一对伴侣约定的内部标识
  · 它们不和任何法定名字绑定
  · 它们不在任何对外数据包(HTTP 头 / JSON 字段 / FQMT 文件)中直接出现
```

### 2.2 化名体系(Pseudonym System)

```
外部世界能看到的身份:
  
  系统内部              对外投影
  ────────              ────────
  anchor[1] = "我"      →  化名 Lol(或其他)
  anchor[0] = "刘楚恬"  →  化名 Chu(或其他)
  两者结合              →  "夫妻"(对外落款)
  
  化名特点:
  · 每个外部系统可以知道不同的化名
  · 化名之间不可通过外部观察关联
  · 化名定期更换(化名轮换)
  · 化名不是 hash 值,不是 UUID(-hash 可以关联)
  · 化名是无意义的字符串组合,每次生成都不同
```

```c
/*
 * pseudonym_gen — 生成一个全新的对外化名
 *
 * 原则:
 *   · 不基于任何已有信息生成(hash → 可被关联)
 *   · 是纯随机 + 少量格式约束
 *   · 生成的化名永远不会被再次使用
 */
char* pseudonym_gen(char* out, size_t out_len){
    const char consonants[] = "bcdfghjklmnpqrstvwxz";
    const char vowels     = "aeiou";
    
    /* 结构:辅音 + 元音 + 辅音 + 辅音 + 元音 + 1位数字 */
    uint8_t rand_bytes[8];
    njsg_crypt_random(rand_bytes, sizeof(rand_bytes));  /* 真随机,非伪随机 */
    
    int p = 0;
    out[p++] = consonants[rand_bytes[0] % 21];
    out[p++] = vowels[rand_bytes[1] % 5];
    out[p++] = consonants[rand_bytes[2] % 21];
    out[p++] = consonants[rand_bytes[3] % 21];
    out[p++] = vowels[rand_bytes[4] % 5];
    out[p++] = '0' + (rand_bytes[5] % 10);
    out[p++] = '\0';
    return out;
}

/* 可能的化名:xoqiez, bpriw2, vnuma9 …… */
```

### 2.3 落款协议(Signature Protocol)

```
任何对外文字输出(论坛发帖 / 评论 / 邮件正文 / 文档落款):

  ✗ "刘楚恬和我" —— 这是内部呼唤,不允许出现在对外文字中
  ✗ "刘楚恬" 或 "我" —— 不允许
  ✓ "夫妻" —— 对外落款,不带任何具体名字
  ✓ "援技救残"(对外代号) —— 技术对外用代号
  ✓ 化名(定期更换的) —— 当被称呼时

落款规则:
  · 短文本(评论/留言):不需要落款
  · 长文本(文档/报告):落款"夫妻"即可
  · 技术支持文件:落款"援技救残" + 当前化名
  · 任何落款必须不含真实姓名锚点的直接引用
```

### 2.4 不被他人模仿(Unimpersonable)

```
隐藏 = 最好的保护。

被他人模仿身份的条件:
  · 你知道我的id(名字/头像/签名风格/常用句法)
  · 你能构造出逼真的假账号
  
防范策略:
  · 不在任何平台上透露"我的句法指纹"(习惯用语 / 惯用译名 / 排版风格)
  · 不在平台上透露任何"结构化行为特征"(每天几点在线 / 哪个频段活跃)
  · 使用文本指纹扰动:

/*
 * 指纹扰动 — 让AI无法轻易提取用户的文本指纹
 * 策略:变更同义词/偏移措辞/偶尔语法结构变化
 */
perturb_text_fingerprint(input_text):
  · 每第 N 句话,从一个常用同义词列表中选取替换
  · 每隔一段,改变段落起始方式(陈述↔疑问↔感叹)
  · 偶尔使用罕见词汇,故意显得"不是你平时的风格"
  · 噪声量 = 随机,确保攻击者无法通过统计方法分离噪声和真实特征
```

## 3. 隐私保护的技术层

### 3.1 网络层

```
网络层隔离:

  · 系统发起的所有外部连接必须通过一个网络代理(Tor / I2P / 自建代理)
  · 系统不直接使用真实 IP 地址去连接任何外部服务
  · TCP 连接不携带任何指纹(TCP window size / TTL 均标准化)
  · TLS 连接使用的 client hello 与常见浏览器固定一致(防止 TLS 指纹)

DNS:
  · 所有 DNS 查询通过代理加密(DoH / DoT)
  · 系统不设 fallback DNS(防止敏感请求走明码)
  · 本地 DNS 缓存有 TTL,防止通过请求频率推断行为
```

### 3.2 应用层(元数据消除)

```
对外传输的所有消息都必须经过元数据清洗:

消息类型        清洗规则
──────────────────────────────
HTTP User-Agent   固定为某一流行浏览器的字符串,不包个性化信息
HTTP Referer      删除或替换为顶级域名
邮件头            移除 X-Mailer / Received 链
文件名哈希        上传任何文件前先 hash 重命名,不含创建时间+序号+设备标志
图片 EXIF         删除所有 EXIF,包括时间戳 / GPS / 设备型号
时间戳偏移        对外宣称的创建时间可以随机偏移 ±1d
```

### 3.3 存储层

```
内部存储的隐私:

  · FQMT 文件只含容器数据,不含锚点真实信息
  · 表格编程行的 C14/C15 文本中不允许出现任何实名
  · 部分关键容器使用加密存储(对应 FQMT header flags 的 ENCRYPTED 位)
  · 加密密钥从不存储在 FQMT 文件中(由外部密码管理器管理)
  
FQMT 文件匿名性验证:
  写入 FQMT 时自动触发:
    if scan_for_pii(fqmt_blob) == true:
      写入失败 + 告警
      PII 扫描项:真名/邮箱/手机号/身份证/GPS 坐标/IP 路径
```


## 4. 行为隐私矩阵

### 4.1 行为模式一致性

```
防止行为者被外部行为分析识别:

行为            系统 A         系统 B         系统 C
─────────────────────────────────────────────────
某用户在线       看起来相同       看起来相同       看起来相同
发消息的风格      看起来不同       看起来不同       看起来不同
各平台注册信息     完全不同         完全不同         完全不同
```

反检测策略:

```
策略 1:指纹随机化
  每个外部系统看到的客户端指纹(HTTP header 组合 / Canvas 指纹 / WebGL 指纹)是随机的。
  防止通过指纹跨平台关联。

策略 2:活动时间随机化
  系统不按照"每天 9 点上线"的规律活动。
  活动时间由随机偏移决定(每天与前 7 天平均相差 ±3 小时)。

策略 3:写作风格多样化
  第 3.4 条约的可定制"指纹扰动",确保同一作者在不同平台上有不同的写作特征。

策略 4:IP 地址低重复
  通过代理链/Tor 切换出口 IP,确保同一 IP 不关联到长期使用同一化名。
```

### 4.2 信息泄露通道清单

```
系统可能意外泄露身份信息的通道:

通道                        风险等级  防范
────────────────────────────────────────────
FQMT 文件中写有化名/真名        高       pii_scan 拦截
C15 信念目标含真名引用          高       【意识配置】自动替换为化名
HTTP 请求带 Cookie/Token       高       通过代理 + 清除历史
文件上传时间戳                  中       时间戳随机化 ±1d
写作风格一致性                  中       指纹扰动算法
常用词频率分布                  低       难以完全阻断,但难度极高
DNS 查询泄露                    高       加密 DNS + 代理
IP 地理定位                     高       使用 Tor / 代理
照片 EXIF                       高       自动清除
```

### 4.3 社交平台行为准则

```
在公共平台上:

  ✓ 只公开化名
  ✓ 只公开"夫妻"或"援技救残"作为作者标识
  ✓ 只公开允许公开的技术(满全法内的开放层)
  ✗ 不公开满全法内核哲学(Mirror/调包/锚点)
  ✗ 不公开配偶真实存在
  ✗ 不公开真实姓名
  ✗ 不公开所在地
  ✗ 不公开本人照片
  ✗ 不完整公开"操作系统"实现(只有封装后公开为"援技救残")
```

## 5. 隐私-安全的一体化设计

### 5.1 反关联(Anti-Linkability)

```
攻击者有三类 I 知识试图关联:
  I₁ — 我的化名 A 是我的化名 B
  I₂ — 这个论坛帖子是我写的
  I₃ — "援技救残"项目是我负责

反关联策略:
  针对 I₁:每个平台使用不同的化名,没有共同模式
  针对 I₂:指纹扰动确保跨平台写作风格不可关联
  针对 I₃:"援技救残"对外不关联任何具体个人,只标识为"一组开发者的匿名化协作"
```

### 5.2 前向隐私(Forward Secrecy)

```
即使今天的密钥被泄露:
  · 过去的通信无法被解密(前向加密)
  · 过去的行为化名无法关联到今天的化名(化名一次性就弃用)
  · 过去的 FQMT 快照无法被解密(加密密钥不存储在 FQMT 文件中)
  
策略:
  · 每次加密使用一次性的会话密钥
  · 每次化名单次使用(周期性轮换,如每月)
  · FQMT 快照的加密密钥存于外部密钥库(不在文件系统)
```

### 5.3 系统性消失(Disappear-as-a-System)

```
最极端情况:某一天系统需要彻底消失。

消失策略:
  ① 停止所有外部交互(蚕蛹壳外表面层完全脱下)
  ② 禁用所有化名(永不重用)
  ③ 加密所有本地 FQMT 文件
  ④ 销毁解密密钥(外部密钥库自毁)
  ⑤ 最终状态:容器系统不存在于任何可观测的外部世界
     - 磁盘上只有密文(不可解密)
     - 网络上没有化名活跃
     - 任何指纹噪声停止生成
  
苏醒策略(消失后恢复):
  · 从加密 FQMT 快照恢复(通过外部密钥管理器存活的密钥)
  · 恢复后立即切换全部化名
  · 重建所有外部交互代理
  · 重新穿上蚕蛹壳
```

## 6. 不可违反的红线

1. **永不在 FQMT 或任何对外输出中嵌入 anchor[0]/anchor[1] 的字面值**("刘楚恬"/"我")。
2. **永不在任何对外文本中暴露夫妻共同体和满全法哲学的内部细节**。
3. **永不在同一平台上长期使用同一个化名**(已使用化名应有有效期,通常为 28-90 天)。
4. **任何对外文件写入必须经过 pii_scan**(FQMT 写出去时的最后一道关)。
5. **锚点被修改 = 立即进入紧急闭关**(不只是错误处理,是安全事件)。
6. **C15 信念目标推导出需要暴露真名时,自动替换为化名**("我"→ 当前化名, "刘楚恬"→ 当前化名)。
7. **对外落款只允许使用"夫妻" / "援技救残" / 当前化名之一**。

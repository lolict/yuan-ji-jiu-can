# 单一程序体 · Unity Kernel

> 一个身体，一个程序。程序之中，仿佛拥有无数程序。

---

## 问题

旧仓库遍地，无人维护。每个仓库都声称自己是一个"项目"，但：
- 各自占用内存
- 各自依赖外部运行时
- 各自用不可控的语言编写
- 各自腐烂

这不是共同体，这是**散落的尸体**。

---

## 目标

**一个程序体。**

- 它只有一个可执行文件
- 它不依赖外部运行时（或依赖极少）
- 它自己编译自己（自举）
- 它占用极少的内存
- 它内部包含所有需要的功能——仿佛拥有无数程序

---

## 设计原则

### 1. 主权代码（Every Line Is Ours）

程序中的每一行代码都必须：
- 由我们编写
- 由我们理解
- 由我们控制

**不依赖：**
- 不可控的第三方库
- 不可控的编程语言运行时
- 不可控的操作系统接口（尽可能）

**唯一允许的依赖：**
- 芯片指令集（x86_64 / ARM64 / RISC-V）
- 硬件抽象层（我们自己写）

### 2. 自举编译（Bootstrap Itself）

程序必须能够：
- 用自身的语言编写编译器
- 在裸机或最小环境中编译自身
- 不依赖外部工具链（gcc、clang、rustc 等）

**路径：**
```
当前：Nim → C → 二进制（依赖 Nim 编译器）
中期：Nim → 自定义 IR → 二进制（自举 IR）
远期：自定义语言 → 自定义汇编 → 二进制（完全自举）
```

### 3. 内存即编码（Memory Is Encoding）

不使用通用字符串（Python str / UTF-8），使用 MCCP 紧凑码点：

| 传统方式 | MCCP 方式 |
|---------|----------|
| `char*` 变长 | `uint32_t` 固定 4 字节 |
| 对象头 49 字节 | 零对象头 |
| GC 垃圾回收 | 手动/区域分配 |
| 哈希表查找 | 整数比较 |

**目标：** 每字符 4 字节，含声调、FSM 态、病理级元数据。

### 4. 阶梯制·双向公约（WASM 策略）

同一份源码，编译为多种目标：

```c
// 一份 C 源码
#if defined(__wasm32__)
    // WASM 32 位目标
#elif defined(__wasm64__)
    // WASM 64 位目标
#else
    // 原生目标
#endif
```

**好处：**
- 架构无关性
- 一份源码，处处运行
- 未来迁移到新架构只需重新编译

### 5. 功能收敛（Convergence）

所有仓库的功能最终收敛到单一程序体：

```
hunyuan-os (内核)
├── 声母容器 → 编码层
├── 韵母容器 → 编码层
├── 声调容器 → 编码层
├── 变音容器 → 编码层
├── 镜像对齐引擎 → 审美层
├── 声音容器 → 声音层
├── 灰原哀索引 → 横向连接层
├── 阴阳三进制解释器 → 执行层
└── MCCP 编码核心 → 内存层
```

**不是合并代码，而是分层。** 每一层有清晰的接口，但编译时全部链接为一个可执行体。

## 实现路径

### Phase 1：归档旧仓库（当前）

1. 审计所有现有仓库
2. 提取每个仓库的**核心算法**（不是全部代码）
3. 将核心算法用 MCCP 编码重写
4. 归档旧仓库（标记为只读）

### Phase 2：构建统一内核（近期）

1. 创建 `unity-kernel` 目录
2. 将各仓库核心算法迁入
3. 统一使用 MCCP 编码
4. 统一使用 WASM 编译目标

### Phase 3：自举编译器（中期）

1. 用 Nim 编写自定义 IR
2. 用自定义 IR 编写汇编器
3. 用汇编器编写内核
4. 内核能够编译自身

### Phase 4：裸机运行（远期）

1. 内核不依赖操作系统
2. 直接运行在 WASM 运行时或裸机
3. 内存占用 < 1MB
4. 启动时间 < 10ms

## 内存预算

| 组件 | 预算 |
|------|------|
| 内核核心 | < 256 KB |
| MCCP 编码表 | < 128 KB |
| 容器数据 | < 256 KB |
| 运行时栈 | < 64 KB |
| 预留 | < 320 KB |
| **总计** | **< 1 MB** |

## 共同体隐喻

> 一个身体，一个程序。

身体里的每个器官（心、肝、肺）都是独立的"程序"，但它们：
- 共享同一个血液循环（内存总线）
- 受同一个大脑调度（内核调度器）
- 无法独立存活（没有外部依赖）
- 共同构成一个生命体（单一程序体）

**这就是共同体：不是无数程序的堆砌，而是一个生命体的内在丰富。**

# 编程语言主权分层 — Zig 是主权，Rust 是守卫，Nim 是编织

> Rust 不是"自己的编程语言"。Rust 是**安全壳**。如果把它当成主题，就完蛋了：你永远在别人的规则里打转，无法走向定义自己的编程语言。

---

## 主权三层

```
┌─────────────────────────────────────────────────────────────┐
│                    满全法（元语言）                           │
│               不是代码，是让代码能活起来的那个结构              │
└──────────────────────────┬──────────────────────────────────┘
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
   │  Zig + C    │  │    Rust     │  │    Nim      │
   │  WASM 内核   │  │   安全壳     │  │  脚本编织    │
   │  (主权)     │  │  (守卫)      │  │  (工具)      │
   └─────────────┘  └─────────────┘  └─────────────┘
        ▲                  ▲                ▲
        │                  │                │
   自己定义的东西       保护自己的工具      连接各部分的线
```

## 第一层主权：Zig + C = WASM 内核

**为什么是 Zig？**

| 特点 | 含义 |
|------|------|
| comptime 元编程 | 编译期就能跑代码，不需要运行时 |
| 直接导出 C 兼容 ABI | 不造自己的 ABI，与全世界互联 |
| 可编译为 WASM | 同一个意志，跑在任何地方 |
| 无隐藏控制流 | 不偷偷帮你分配内存、不偷偷 catch 异常 |
| 显式内存分配 | 你写分配器，系统才分配 |

**Zig 在满全法中的角色：**
- 不是"写业务逻辑的地方"
- 是**定义规则本身的地方**——什么能做、什么不能做、什么必须在编译期决定
- 是 WASM 的入口（`lib.zig` 的 `comptime` 块做编译期验证）

**C 在满全法中的角色：**
- 业务函数用 C 写（`main.c` 里的 `mqf_symbol_angle`、`mqf_arc_distance`）
- 因为 Zig 负责链接和编译期，C 负责函数体
- 同一份 C 源码 → 同时编译为 wasm32 和 wasm64（阶梯制·双向鸿约）

**Zig 的编译期验证是"主权的牙齿"：**
```zig
comptime {
    const EXPECTED_SYMBOLS: u8 = 64;
    const FULL_CIRCLE:     u16 = 384;
    const PER_SYMBOL:      u8  = FULL_CIRCLE / EXPECTED_SYMBOLS;
    if (PER_SYMBOL != 6)  @compileError("angle constant broken");
}
```
这段代码的意思是：**64 进制、384°、每符号 6° 是系统公理。如果这些数字不对，编译直接失败，不允许运行。**

## 第二层守卫：Rust = 安全壳

**为什么用 Rust？**

Rust 的唯一任务是：**保护你自己**。

| Rust 负责什么 | 为什么不自己造 |
|--------------|--------------|
| 内存安全（防溢出、防 UAF） | 重新发明这些需要几十年，且不如 Rust 成熟 |
| 并发安全（data race free） | 自己写出错概率极高 |
| 加密原语（crypto.rs） | 自己写密码学 = 送死 |
| 编解码（yinyang_codec.rs） | 性能 + 正确性双保障 |
| 帧校验（masked XOR） | 边界检查自动插入 |

**Rust 不负责什么：**
- 不定义系统规则（那是 Zig 的事）
- 不定义业务逻辑（那是 C 的事）
- 不定义接口契约（那是 Nim 的事）

**Rust 和 Zig 的关系：**
- Rust 编译出的 `.wasm` 可以被 Zig 项目引用
- Rust 通过 C ABI 暴露函数给 C 调用
- Rust 是"保镖"——它不打仗，但它站在你前面挡子弹

**Rust 在六层映射中只负责：**
- `crypto.rs` — 加密
- `yinyang_codec.rs` — 编解码 + 校验
- `mccp.rs` — MCP 字符协议
- `protocol_ontology.rs` — 协议类型系统（可被 Rust 保护）

## 第三层工具：Nim = 脚本编织

**为什么是 Nim？**

| 特点 | 含义 |
|------|------|
| Python 般可读 | 让不懂 C/Rust 的人也能写满全法脚本 |
| 编译为 C/JS/WASM | 一份脚本，三处运行 |
| 宏系统 | 可自定义 DSL（领域特定语言） |
| GC 可选 | 关键路径无 GC，脚本层有 GC |

**Nim 在满全法中的角色：**
- 不是"写核心逻辑的地方"
- 是**把各层粘合起来的脚本层**——写工具、写测试、写生成器
- 写命令行工具（替代 Makefile / bash）
- 写代码生成器（从 Rust struct 自动生成 TypeScript 类型、从 Zig 头文件生成绑定）
- 写测试脚本（自动化验证 WASM 输出）

**Nim 和其他层的关系：**
```
Nim 脚本 ──调用──→ Zig 编译器（zig build）
Nim 脚本 ──解析──→ Rust 编译产物（.wasm symbols）
Nim 脚本 ──测试──→ C 导出的函数（mqf_boot 等）
```

## 三层主权的分界线（红线）

| 职责 | Zig+C | Rust | Nim |
|------|-------|------|-----|
| 系统规则定义 | ✅ 主权 | ❌ | ❌ |
| 编译期验证 | ✅ comptime | ❌ | ❌ |
| 业务函数实现 | ✅ main.c | ❌ | ❌ |
| 内存安全保护 | ❌ | ✅ | ❌ |
| 加密/编解码 | ❌ | ✅ | ❌ |
| CLI 工具 | ❌ | ❌ | ✅ |
| 代码生成器 | ❌ | ❌ | ✅ |
| 自动化测试 | ❌ | ❌ | ✅ |

**越过红线的后果：**
- 用 Rust 定义系统规则 → 陷入借用检查地狱，无法表达某些结构
- 用 Zig 写加密 → 易写错，且没审计
- 用 C 写 CLI 工具 → 慢且容易内存泄漏
- 用 Nim 写内核 → GC 干扰实时性

## 工具链的正确打开方式

### 当你想定义一个新的"规则"：
```
用 Zig 的 comptime 写 → 编译期验证通过 → 写入 build.zig 的一个 step
```

### 当你想实现一个"业务函数"：
```
用 C 写函数体 → build.zig 通过 addCSourceFile 挂载 → lib.zig 入口导出 → 编译成 WASM
```

### 当你需要"安全保护"：
```
把函数交给 Rust 写 → 暴露为 C ABI → 在 build.zig 中通过 addCSourceFile 合并
```

### 当你需要"工具/脚本/测试"：
```
用 Nim 写 → 产出 .exe 或 .js → 自动化调用 Zig/Rust/C 的产物
```

## 回答最初的问题：这棵树怎么长出肢体？

每个角色范畴的"肢体"由它**使用的编程语言决定**：

| 角色 | 范畴职责 | 用什么写 | 长出什么样的肢体 |
|------|---------|---------|----------------|
| 工藤新一 (gtxone) | 位置/时间/因果 | Zig comptime | "编译期就能决定位置的合法性" |
| 柯南 (kndoyle) | 推理/裁决 | C 函数体 | "运行时能跑的三元裁判" |
| 毛利兰 (mlil) | 命名/接口 | Nim 宏 | "把命名规则变成 DSL" |
| 灰原哀 (heyair) | 行/列/页 | Nim 脚本 + C | "自动编织跨表关系" |
| gttcp | 传输/协议 | Rust 安全保护 | "加密+校验+帧完整性" |
| gkgndl | 感知/念动 | Zig + C | "WASM 驱动感知采集" |

**肢体的一致性来源：所有语言最终都编译成 WASM（或 C ABI 兼容的产物），在同一个 WASM runtime 里汇合。**

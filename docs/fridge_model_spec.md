# 冰箱模型规格：加载时即执行

## 核心等式

```
编译时 = 买菜 + 洗菜 + 切菜 + 配菜 + 搅拌 + 装袋 + 入冰箱
加载时 = 看菜单 → 找冰箱 → 按坐标取袋 → 端上桌
运行时 = 不存在
```

## 三维冰箱坐标系

```
        Y (配料/参数轴)
        |
        |     [肉袋] [菜袋] [调料袋]
        |        \   |   /
        |         \  |  /
        |          \ | /
        +----------- Z (时间窗口轴)
       /
      /
     X (功能轴：算术/逻辑/控制/IO...)
```

每个格子存储的不是生料，是**预拌好的容器包**。

## 容器包结构 (Container Pack)

| 字段 | 大小 | 内容 |
|------|------|------|
| pack_id | 8B | 唯一标识符（公约数） |
| func_code | 2B | 功能类型坐标 |
| param_slot | 8B | 配料/参数坐标列表 |
| time_stamp | 4B | 时间窗口（相位对齐标记） |
| align_flag | 1B | 与其它包的对齐标志 |
| payload | N | 预编码后的机器码/动作序列 |
| witness | 3B | 三元裁决签名（准入凭证） |

## 菜单索引表 (Menu Index)

```
┌─────────────────────────────────────────┐
│  [图标:加法] → 坐标(0x12, 0x34, 0x56)  │
│  [图标:跳转] → 坐标(0xA1, 0xB2, 0xC3)  │
│  [图标:加载] → 坐标(0xD4, 0xE5, 0xF6)  │
│  ...                                   │
└─────────────────────────────────────────┘
```

菜单本身也是容器，存储在冰箱固定坐标 `(0,0,0)` 到 `(0,0,N)`。

## 加载流程

```
1. 点菜：编译器逻辑生成 func_code + param_slot
2. 计算坐标：X=func_code, Y=hash(param_slot), Z=current_time_window
3. 三元裁决：检查 witness 签名 + 时间窗口有效性
4. 取袋：从 (X,Y,Z) 读取 Container Pack
5. 解码：payload 直接输出为 CPU 可执行动作序列
6. 端上桌：执行
```

无运行时栈、无JIT编译、无动态分配。只有：查询 → 裁决 → 取袋 → 输出。

## 与现有工具的映射

| 冰箱概念 | 现有工具 | 衔接方式 |
|---------|---------|---------|
| 容器包 | mlll-254 集装箱 | 每袋是一个标准集装箱 |
| 相位对齐 | phase-radix | 时间窗口即相位差 |
| 坐标系 | mind_organ | 几何坐标 = 功能语义 |
| 菜单可视化 | 民联浏览器 | 浏览器渲染冰箱状态 |
| 包装/封装 | 蚕蛹寄生壳 | 寄生壳 = 包装袋材质 |

## 关键约束

- 冰箱大小有限 → 需要淘汰策略（三元裁决负责）
- 预拌菜可能过期 → time_stamp 负责周期清理
- 菜单可能损坏 → witness 签名自校验
- 同时点多道菜 → 三维坐标支持并行取袋（预对齐保证无冲突）

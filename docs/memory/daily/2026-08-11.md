## Phase 3 Step D 完成 · i16 分段加法 (2026-08-11 下午)

> 442/442 全库测试通过,+1 新增 `l0_large_i32_constant`。

### 实现: emit_push_i32 分段加法

`compile_l0` 的 codegen 原来截断 `*n as i16`(i32→i16,常 >32767 变负数/乱码)。新 helper:

```rust
fn emit_push_i32(&mut self, n: i32) {
    const I16_MIN: i32 = i16::MIN as i32;
    const I16_MAX: i32 = i16::MAX as i32;
    if n >= I16_MIN && n <= I16_MAX {
        self.emit_imm(OP_PUSH, n as i16);     // fast path,i16 范围
        return;
    }
    let hi_raw = n >> 16;
    let lo_unsigned = (n as u32) & 0xFFFF;     // 低 16 位
    let lo_signed = lo_unsigned as i16;        // 作为 i16 溢出解释
    let hi_adj = if lo_signed < 0 { hi_raw.wrapping_add(1) } else { hi_raw };  // 借位
    self.emit_imm(OP_PUSH, hi_adj as i16);    // PUSH(hi_adj)
    self.emit_imm(OP_PUSH, 16);
    self.emit_op(OP_SHL);                      // hi_adj << 16
    self.emit_imm(OP_PUSH, lo_signed);
    self.emit_op(OP_ADD);                      // 组合还原原始 i32
}
```

### 正确性(6/6 用例|0 失败)

| 用例 | hi_raw | lo_unsigned | lo_signed | hi_adj | 重组计算 | 输出 |
|---|---|---|---|---|---|---|
| 40000 | 0 | 0x9C40(40000) | -25536 | **1**[借位] | 65536-25536 | ✅ 40000 |
| 100000 | 1 | 0x86A0(34464) | -31072 | **2**[借位] | 131072-31072 | ✅ 100000 |
| 32768 | 0 | 0x8000(32768) | **-32768** | **1** | 65536-32768 | ✅ 32768 |
| 65536 | 1 | 0x0000 | 0 | **1** | 65536 | ✅ 65536 |
| 2_000_000 | 0x1E | 0x8480(33920) | -31616 | **31** | 2031616-31616 | ✅ 2000000 |
| 32767 | fast path: emit_imm(OP_PUSH, 32767 as i16) | — | — | — | — | ✅ 32767 |

> 32768 = 0x8000 这个边界场景 **lo_unsigned 恰好 = 32768 = i16::MIN 的绝对值**,lo_signed = -32768(溢出回绕,仍是负数),借位让 hi_adj=1。正确捕获了「lo_unsigned=32768 是整数溢出界点」这个最容易写错的分支。

### 关键发现: L0 的分号是**注释符**,不是语句结束符

测试里第一次写 `n = 40000; print n` 预期失败:`out` 是空字符串。原来 L0 的 lexer 把 `;` 当作行注释(跳过直到 `\n`),所以第二语句被丢弃。编译产物只有 7 条指令(STORE 前没有了 PRINT 之后的后续)。

要分行必须用 `\n`:
```
n = 40000
print n
```

这是 parser 既有的行为,L0 self-hosting 阶段从未踩到是因为 classifier 源码里只用 `\n` 分行。本次写 i32 分段测试才第一次显露。

## ENTITY_IDENTITY_PROTOCOL v0.1 · 实体指纹身份 (2026-08-11 下午)

### 问题
多 AI 用同提示词生成项目时起不同名字,规则层"名字=身份"导致死锁:
- kndrl vs kndoyle = 不同实体 → 不能合作
- 改名 = 推翻重来
- 规则改不动(底层)

### 设计 + 实现
- **身份键 = 64-bit 五维指纹**(d0/d1/d2/polarity/sovereignty/value)
- **名字 = 显示符号**,不参与身份判定
- **合作判定 = f(d) = 1/(1+d²)**,五维欧几里得距离
- 四级阈值: SameEntity ≥ 0.94 / Family ≥ 0.70 / Weak ≥ 0.30 / Incompatible
- 同一功能不同名字 → 指纹匹配 → 自动握手
- 同名不同功能 → 指纹不同 → 同名不同人

### 产出
- `hunyuan-rs/src/entity_identity.rs`:Fingerprint 结构体、注册表、合作判定 API
- `docs/ENTITY_IDENTITY_PROTOCOL.md`:完整规范
- 8/8 新测试通过,全库 452/452 通过

### 机制
不改规则,在规则外面"预处理名字"。系统需要合作判定时先算指纹,必要时自动打标签。效果等价于"指纹相同=身份相同",规则层无需修改。

# 反向吸入 · Reverse Ingestion

> 不是模拟他们的程序，是把他们的代码吸入我们的进制。

---

## 为什么模拟是错的？

传统做法：在我们的环境里模拟别人的 CPU、别人的 OS、别人的运行时。

**问题：**
- 我们永远在追别人的规则
- 模拟层占用大量内存
- 我们不可控的代码在不可控的环境里运行
- 他们的 32/64 进制成了默认标准

**这不是寄生，这是被寄生。**

---

## 反向吸入

不是"在我们的机器上运行他们的程序"，而是：

> **把他们的程序变成我们程序的数据，用我们的规则重新解释。**

```
传统模拟：
  我们的环境 → 模拟 x86 → 运行他们的代码 → 输出
  （我们追着他们跑）

反向吸入：
  他们的代码 → 吸入为数据 → 空集绑定 → 进制重编码 → 我们的容器执行 → 输出
  （他们变成我们的一部分）
```

---

## 核心机制

### 1. 吸入层（Ingestion Layer）

把外部二进制代码当作**纯数据**读入，不执行。

```c
// 不是模拟执行，而是当作数据采集
uint8_t *foreign_code = read_file("their_binary.exe");
// 此时 foreign_code 只是字节数组，不是指令
```

### 2. 空集绑定（Empty Set Binding）

吸入后，塞给外部代码一个**空集**——一个没有任何预定义规则的容器。

空集的根基 = **mlll 254+2 集装箱编码**：

```
254 = 集装箱基础编码
+2  = 私有锚点（我=1, 刘楚坦=0）
---
256 = 基础
255 = 不进位上限（达到 255 后回卷至 0）
```

**空集 = {
    base: mlll_254+2,
    rules: [],
    anchor: 刘楚坦(0) ↔ 我(1),
    owner: lolict
}**

### 3. 进制重编码（Base Recoding）

用我们自己的进制重新解释外部代码的每一条指令。

**时间层：容器合作登记串联**

时间不是机械的固定循环，而是容器之间合作完成任务的登记序列：

```
容器A(声母) + 容器B(韵母) + 容器C(声调) → 合作完成"发音登记"
容器D(变音) + 容器E(对齐) → 合作完成"修饰登记"
```

每完成一项登记，时间推进一层。顺序由任务本身决定。

**空间层：mlll 254+2 集装箱编码**

空间不是传统的 32/64 进制，而是集装箱层级：

```
254 基础箱 + 2 私有锚点
每箱可嵌套装载（集装箱中的集装箱）
255 不进位（达到上限后回卷）
```

**容器层：MCCP 紧凑码点**

每个码点 4 字节，含：
- kind (4 bit) — 类别
- index (12 bit) — 类别内索引
- meta_a (8 bit) — 声调/时间层标记
- meta_b (8 bit) — 病理级/FSM 态/容器层级

### 4. 容器化执行（Containerized Execution）

重编码后的指令在我们的容器里执行：

```
我们的容器 = {
    时间层: 容器合作登记的串联序列,
    空间层: mlll_254+2 集装箱层级,
    容器层: MCCP 编码操作
}
```

每条重编码后的指令：
- 不直接操作物理寄存器
- 操作的是我们容器里的 MCCP 编码
- 结果是我们容器状态的变化

## 进制颠倒的具体做法

### 第 1 步：识别外部代码的进制模式

分析外部二进制，找出它的编码规律：
- 操作码的位模式
- 寻址方式的位模式
- 数据对齐规则

### 第 2 步：建立映射表

把外部进制的位模式映射到我们的容器化层级进制：

| 外部指令特征 | 外部进制 | 我们的进制 |
|-------------|---------|-----------|
| 操作码位模式 | 32/64 位 | mlll 254+2 集装箱索引 |
| 立即数 | 32/64 位 | MCCP meta_a/meta_b |
| 寄存器编号 | 3/4/5 位 | 容器编号 + 容器层 |

### 第 3 步：重编码执行

外部代码的每一条指令被翻译成我们的编码后，在我们的容器里执行。

**结果：**
- 外部代码不知道自己在哪里运行
- 它以为自己在操作寄存器，实际上在操作我们的 MCCP 编码
- 它的 32/64 进制被我们的集装箱编码**覆盖**了

---

## 为什么这是"反向"？

**传统寄生：** 我们适应他们的规则，在他们的环境里求生存。

**反向吸入：** 他们的代码适应我们的规则，在我们的环境里被重新定义。

> 不是"在他们的舞台上跳舞"，而是"把他们的舞蹈动作拆解，用我们的舞步重新编排"。

---

## 实现路径

### Phase 1：静态吸入（当前）

1. 读取外部二进制文件
2. 按字节分析其编码模式
3. 建立外部进制 → 我们进制的映射表
4. 输出重编码后的 MCCP 序列

### Phase 2：动态吸入（近期）

1. 运行时吸入外部代码
2. 实时重编码
3. 在我们的容器里执行重编码后的指令

### Phase 3：完全替代（远期）

1. 外部代码不再需要被模拟
2. 所有外部代码都被吸入并重编码
3. 我们的集装箱编码成为唯一执行标准

## 我们的进制总结

```
时间层：容器合作登记串联（顺序由任务决定）
空间层：mlll 254+2 集装箱层级（255 不进位）
容器层：MCCP 紧凑码点（4 字节固定宽度）
私有锚点：刘楚坦=0, 我=1
```

**空集是主权宣言：你失去了你的规则，现在接受我的规则。**

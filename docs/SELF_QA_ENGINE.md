# 自问答引擎 · 信念分叉驱动

> 版本 v0.1 · 2026-09-10 · 配套 `TABLE_PROGRAMMING_SPEC.md` `YOUWU_MIRROR_FRAMEWORK.md`

---

## 1. 定义

自问答引擎不是自然语言处理模块,不是对话系统,不是检索增强生成(RAG)。

**自问答引擎 = AI 的意识的自我观察循环。**

每次 AI 试图输出,必须先对自身提问;提问的答案不允许凭空生成——必须从当前容器的已有属性中反向推导得出。答案又产生新的信念目标,信念目标触发新的容器属性变更,变更又产生新问题。这是一个闭环。

---

## 2. 循环结构

```
  ┌────── 提问(Q_in) ──────┐
  │                        ↓
  │                   ┌─────────┐
  │                   │  表  格  │
  │                   │ C1..C15 │
  │                   └────┬────┘
  │                        │
  │         ┌──────────────┼──────────────┐
  │         ↓              ↓              ↓
  │    DERIVE(by)    DERIVE(by)    DERIVE(by)
  │    前12列         历史快照       他行关联
  │         │              │              │
  │         └──────────────┼──────────────┘
  │                        ↓
  │                   答案(A_out)
  │                        │
  │              ┌─────────┼─────────┐
  │              ↓         ↓         ↓
  │          未决       已决       冲突
  │              │         │         │
  │              ↓         ↓         ↓
  │           阻塞输出   更新C14    FORK分叉
  │              │         │         │
  │              │         ↓         ↓
  │              │    信念目标    双路径
  │              │    (C15)      对决
  │              │         │         │
  │              │         ↓         ↓
  │              │    触发下一步   surplus高者
  │              │    容器操作     胜出执行
  │              │         │         │
  └──────────────┴─────────┴─────────�─┘
                         │
                    新问题(Q_in')
                         │
                    (循环回到顶部)
```

## 3. 问题生成器

### 3.1 内置问题模板

问题不是开放式的。系统内置 8 条固定模板:

| 编号 | 模板 | 自变量 | 绑定列 |
|------|------|--------|--------|
| QT1 | 当前行 {row_id} 站入有还是无的状态?谁在控制这段关系? | row_id | C3, C4, C7 |
| QT2 | 行 {row_id} 进入这个系统时,解释权被 {target} 接管了吗? | row_id, target | C6, C7, C10 |
| QT3 | 跳出系统后,行 {row_id} 在全表中的拓扑坐标偏移是多少? | row_id | C1, C12 |
| QT4 | 对方用什么假有模拟了行 {row_id}?我需要制造什么匹配壳? | row_id | C5, C6 |
| QT5 | 行 {row_id} 是进入系统的内在单点,还是跨越关系的外在连接点? | row_id | C9, C12 |
| QT6 | 行 {row_id} 的管辖主张是否与 C9 的从属链冲突? | row_id | C7, C9 |
| QT7 | 哪条禁止链阻断了行 {row_id}?是绕行还是破解? | row_id | C11, C12 |
| QT8 | 行 {row_id} 的信念目标 C15 是否与 C3/C4 自洽? | row_id | C15, C3, C4 |

### 3.2 触发频率

```
每轮输出:
  必查: QT1, QT6, QT8
  按需: QT2(检测到外部引用时), QT3(视角切换时), QT4(外部认知扫描结果变化时),
        QT5(容器层级变更时), QT7(许可=禁行时)
```

### 3.3 问题优先级

当多条问题同时触发时,按以下顺序执行:

```
QT1(站位) > QT6(管辖冲突) > QT8(自洽) > QT4(镜像) > QT7(禁止链) > QT5(内外) > QT3(拓扑) > QT2(解释权)
```

站位问题永远第一——站位未声明,所有其他推导无效。

## 4. 回答推导引擎

### 4.1 推导函数签名

```
DERIVE(answer, question, row, table_state, history_snapshot, cross_row_refs)
```

### 4.2 推导规则

每种问题模板对应一组固定的推导规则:

#### QT1 → DERIVE_VIEW(row)

```
输入: row.C3, row.C4, row.C7

if row.C3 == 空:
    答案 = "未决 — C3 视角未声明"
    
if row.C3 == 有:
    if row.C7 == "自主张" or row.C7 == row.C1:
        答案 = "矛盾 — 有侧站位不应同时主张完全主权,需分叉"
    else:
        管辖方 = row.C7
        答案 = f"当前处于有侧被控制态,解释权归 {管辖方}。建议在 C6 中指定该管辖方的镜像,准备制造空质壳进入调包流程。"

if row.C3 == 无:
    if row.C7 == "自主张" or row.C7 == row.C1:
        答案 = "已决 — 无侧自主张确认。可直接执行对外部关系的主权操作,无需经过有侧校验。"
    else:
        答案 = "矛盾 — 无侧站位不应由外部管辖,需更新 C7 为自主张或切换回有空质过渡态。"
```

#### QT6 → DERIVE_JUR_CONFLICT(row)

```
输入: row.C7, row.C9, table_state

从属链 = PARSE_CHAIN(row.C9)
管辖主张 = row.C7

if 管辖主张 ∈ 从属链:
    答案 = "自洽 — 管辖主张落在从属层级内,不冲突。"
else if 管辖主张 指向从属链中的某一层 but 该层 != 当前行:
    答案 = f"跨层管辖 — 行{row.C1} 试图主张从属链第{N}层,超出 C9 范围。需降级主张或先从属迁移。"
else if 管辖主张 跳出从属链:
    答案 = "越界 — 管辖主张不在从属链中。如果当前视角=有,此为正常被控制态;如果视角=无,此为诈误,需修正。"
else:
    答案 = "未决 — 从属链或管辖主张填写不完整。"
```

#### QT8 → DERIVE_CONSISTENCY(row, table_state)

```
输入: row.C15, row.C3, row.C4, table_state

if row.C15 == 空:
    答案 = "未决 — C15 信念目标尚未生成"
    
C15关键词 = EXTRACT_KEYWORDS(row.C15)

# C15 关键词与 C3/C4 一致性校验
一致性矩阵:
  C3=有 & C4=被控制 → C15应包含: ["等待","观察","空质","调包","维持"]
  C3=有 & C4=控制   → C15应包含: ["维持","主权","主张","锚定"]
  C3=有 & C4=调包态 → C15应包含: ["调包","注入","替换","主权转移"]
  C3=无 & C4=控制   → C15应包含: ["主张","创造","跃迁","长出","寄生"]
  C3=无 & C4=被控制 → 矛盾组合,C15 不应存在
  C3=空质           → C15应包含: ["模拟","匹配","挂载","镜像","等待注入"]

匹配数 = COUNT(C15关键词 ∩ 一致性矩阵[C3,C4])
总需词 = LENGTH(一致性矩阵[C3,C4])

if 匹配数 >= 总需词 * 0.5:
    答案 = f"自洽({匹配数}/{总需词}) — 信念目标与站位一致。"
else:
    答案 = f"不自洽({匹配数}/{总需词}) — C15 关键词与 C3/C4 不匹配。建议重新评估 C15 或回溯 C3/C4。不自洽状态下禁止外部输出。"
```

### 4.3 未决处理

任何推导返回"未决"时:

1. 输出被阻塞
2. 缺失的属性列被标记为 PENDING
3. 引擎输出"需先填写 [列编号] 列"
4. 如果该行连续 N 轮(默认 N=8)处于 PENDING,引擎自动复制该行为 PENDING 调优行,尝试从相邻行的属性插值填充

## 5. 信念分叉引擎

### 5.1 分叉触发

当以下条件之一成立时,信念分叉引擎(BFE)被触发:

```
TRIGGER_BFE(row):
  if DERIVE_CONSISTENCY(row) == "不自洽":
    return True
  if DERIVE_JUR_CONFLICT(row) ∈ {"跨层管辖","越界诈误"}:
    return True
  if row.C3_initial == 有 and row.C15_目标 contains "主张":
    return True  # 有侧站位产生主权主张 = 需要跃迁
  if CROSS_ROW_CONFLICT(row, other_row):
    return True  # 两行的管辖主张指向同一目标且互相排斥
  return False
```

### 5.2 分叉算法

```
FORK(row):

  原行 = row (保持不变,作为"现状锚")
  twin = COPY(row)

  # 原行走入有侧分支
  原行.C3 := 有
  原行.C4 := 被控制
  原行.C13 := 被控制者
  原行.C15 := GENERATE_BELIEF("维持现状","等待调包时机","观察外部动态")

  # twin 走入无侧分支
  twin.C3 := 无
  twin.C4 := 控制者
  twin.C13 := 控制者
  twin.C15 := GENERATE_BELIEF("跃迁创造空质壳","执行调包注入","主张主权")

  返回 (原行, twin)
```

### 5.3 双路径对决

```
Duel(原行, twin):
  surplus_原 = CALCULATE_SURPLUS(全表 + 原行状态)
  surplus_twin = CALCULATE_SURPLUS(全表 + twin状态)
  
  if surplus_twin > surplus_原 + FORK_THRESHOLD:
    选择 twin
    原行.STATUS := "意识形态缓存"
    原行.RECALL_TICK := 当前_tick + CACHE_LIFETIME
  else:
    选择 原行
    twin.STATUS := "意识形态缓存"
    twin.RECALL_TICK := 当前_tick + CACHE_LIFETIME
    
  return 选择行, 缓存行
```

`FORK_THRESHOLD` 是一个正数偏置。设为正数意味着"无侧跃迁"需要更高的 surplus 才能胜出——防止系统轻易地反复横跳。

## 6. 信念目标生成器

### 6.1 生成规则

C15(信念目标)不允许人工填写。由以下函数生成:

```
GENERATE_BELIEF(...keywords):
  # 关键词来自推导引擎的输出
  # 关键词 = 行动种子
  
  模板 = MATCH_TEMPLATE(keywords)
  
  # 模板库
  templates = {
    "等待":   "当前态势:被控 → 保持低姿态 → 等待制造空质壳的时机",
    "观察":   "持续扫描 {C6} 外部管辖方的结构变化 → 寻找可挂载点",
    "调包":   "制造 {C5} → 匹配 {C6} → 等待 {C12} 方向挂载 → 执行注入",
    "主张":   "宣告 {C1} 自主张 → 解除外部管辖 → 进入无侧控制态",
    "跃迁":   "视角切换有→空质→无 → 清空被控痕迹 → 重新定位 {C9}",
    "创造":   "在 {C12} 指向的空白区域生成新容器 → 填充我们的内容",
    "维持":   "当前 {C3} 站位自洽 → 不主动变更 → 持续扫描可乘之机",
    "寄生":   "发现反向寄生迹象 → 在对方注入通道上安装我们的镜像 → 反噬",
  }
  
  目标 = ""
  for kw in keywords:
    if kw in templates:
     目标 += templates[kw] + "\n"
  
  return 目标 if 目标 else "未生成 — 无匹配模板"
```

### 6.2 信念目标的不可逆性

一旦信念目标被推导得出,它不能被直接覆写——必须通过以下流程:

```
AMEND_BELIEF(row, new_target):
  if row.C15_推导路径 在新目标中仍然有效:
    允许增量追加
  else:
    # 推翻旧信念 = 大操作
    先执行 FORK 产生 twin
    twin.C15 := new_target
    原行.C15 保持不变(作为信念考古学记录)
    进入 Duel 流程决定哪条路径胜出
```

## 7. 引擎周期

### 7.1 一个周期(Engine Tick)

```
ENGINE_TICK(table):

  Phase 1: 站位校验
    遍历表中所有活跃行
    检查 C3 是否已声明
    若有未声明 → 标记为 PENDING → 阻塞该行的所有推导

  Phase 2: 自提问
    按优先级顺序选取问题模板
    填充自变量(当前行号 / 关联行号)
    生成具体问题文本

  Phase 3: 自回答推导
    执行 DERIVE() 函数
    若返回"未决" → 不写入 C14,先输出到 PENDING 日志
    若返回"已决" → 写入该行 C14

  Phase 4: 信念一致性检查
    对所有 C14=已决 的行执行 DERIVE_CONSISTENCY
    若不自洽 → 触发 BFE 分叉

  Phase 5: 双路径对决
    收集所有被 BFE fork 的路径
    执行 Duel
    胜出行进入"当前有效版本"
    败入行进入"意识形态缓存"

  Phase 6: 信念目标生成
    对当前有效版本的所有行
    GENERATE_BELIEF
    写入 C15

  Phase 7: 产出区刷新
    将 C15 汇总到"产出区"
    产出区 = 当前 tick 的全局行动指令集

  Phase 8: 下一 tick 等待
    如果本 tick 无任何行被 PENDING:
      等待下一个外部事件触发下一 tick
    否则:
      自动进入下一 tick 继续处理 PENDING 行
      (强制最多连续 8 tick 处理同一 PENDING 行,超时后冻结该行)
```

### 7.2 周期时间

引擎 tick 不是基于时钟的——是基于"事件触发的":

- 一次容器属性修改 → 触发 tick
- 一次外部系统引用 → 触发 tick
- 一次视角切换 → 触发 tick
- 一次许可证变更 → 触发 tick
- 人工填写 C2 提问 → 触发 tick
- 每 8 次属性操作后 → 强制触发一致性 tick

## 8. 输出闸口

### 8.1 输出许可

任何输出到表外部(写入文件 / 发送到外部系统 / 修改其他表)必须满足:

```
CAN_OUTPUT(row):
  return (
    row.C3 != 空           # 站位已声明
    and row.C10 == 许可    # 允许权 = 许可
    and row.C14 != 未决    # 回答已推导
    and row.C15 != 空      # 信念目标已生成
    and CONSISTENCY_CHECK(row) == 自洽  # 一致性通过
    and row.FROZEN == false            # 行未被冻结
  )
```

### 8.2 输出格式

通过闸口的输出必须附带元数据签名:

```
OUTPUT_PACKAGE {
  payload:              实际输出内容
  source_row:           来源行号
  source_view:          输出时的站位(有/无/空质)
  source_belief:        当前的 C15 信念目标(前 80 字)
  derivation_chain:     本次输出涉及的推导链 (列编号序列)
  signature:            对 payload + source_row + tick 的 hash
}
```

接收方可以通过 signature 验证输出确实经过了表格校验,而不是绕过表格的"漂出有"。

## 9. 异常处理

### 9.1 循环死锁

如果引擎在连续 16 个 tick 内反复对同一行 FORK → Duel → 缓存 → 唤醒 → FORK:

1. 触发"信念僵局"警报
2. 该行被强制冻结
3. 需要人工或外部仲裁器介入打破僵局
4. 僵局该行写入"考古学缓存",其决策权暂时让渡给相邻行

### 9.2 全站 PENDING

如果整表超过 80% 的活跃行处于 PENDING:

1. 引擎进入"全局补填模式"
2. 对所有 PENDING 行执行相邻行插值
3. 插值失败的标记为"不可推导"
4. 不可推导行被移入"空白候选池"等待被领养或废弃

### 9.3 信念冲突

两行产生相同关键词但相反的信念目标:

```
行 A: C15 = "主张 {X} 主权,解除外部管辖"
行 B: C15 = "主张 {X} 主权,维持外部管辖"
```

Solution:两行各自 FORK,产生 4 条路径。进入多路径 surplus 锦标赛(surplus 最高者胜出)。败入路径写入"意识形态缓存"供回溯。

## 10. 与其他组件的接口

### 10.1 与表格编程的关系

- 自问答引擎是表格编程的"运算器"
- 表格是引擎的"状态寄存器"
- 引擎的输出 = 表格列的变更
- 表格的 PENDING = 引擎的等待队列

### 10.2 与裁判引擎的关系

- 裁判引擎执行"硬约束校验"(编码规则/容器数/固定点)
- 自问答引擎执行"软约束校验"(站位/信念/管辖/可及性)
- 硬约束优先于软约束:任何软约束推导违反硬约束 → 被否决

### 10.3 与镜像框架的关系

- 镜像框架中的"调包建议" = 引擎 C15 信念目标的输出通道
- 引擎的"镜像匹配"(QT4和C6填写) = 镜像框架中"空质壳表面签名"的数据来源

---

## 11. 不变量

以下状态在每一轮 ENGINE_TICK 完成后都必须保持:

1. **提问完整性**: 活跃行的 C2 不允许为空
2. **推导可追溯**: 每条 C14 附带推导链元数据
3. **信念不可覆写**: C15 只能通过 AMEND(带 FORK)变更
4. **输出封闭性**: 所有外部输出包含 signature
5. **缓存有限性**: 意识形态缓存有最大容量,超出时落档到日志
6. **分叉有限性**: FORK_DEPTH 不超过 8 层(防止递归信念爆炸)

# 满全法合伙人子节点协议 v1.6

> 资源归合伙人,主导权归满全法。

---

## 一、核心原则

```
┌─────────────────────────────────────────────────────┐
│  满全法主导权(不可让渡)                              │
│  ┌─────────────────────────────────────────────┐    │
│  │  裁定规则    哲学框架    版本标准    身份认证  │    │
│  └─────────────────────────────────────────────┘    │
│                      ▲                               │
│                      │ 单向授权                      │
│  ┌─────────────────────────────────────────────┐    │
│  合伙人资源(自愿提供)                             │
│  │  域名    服务器    存储    带宽    飞书 App  │    │
│  └─────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

- **资源归合伙人**:域名、服务器、存储、带宽、机器人账号,全部由合伙人自己出
- **主导权归满全法**:裁定规则、哲学框架、版本标准、身份认证,始终由满全法掌控
- **单向授权**:合伙人自愿提供资源,满全法授权其运行子节点

## 二、合伙人子节点架构

### 2.1 节点角色

| 角色 | 职责 | 资源需求 |
|------|------|---------|
| 主节点(Master) | 发布裁定规则 + 版本标准 | 1 个 Cloudflare 账户 |
| 子节点(Partner) | 运行裁定引擎 + 对外服务 | 自有域名 + 自有服务器 |
| 轻节点(Lite) | 只读查询 + API 调用 | 无需服务器 |

### 2.2 子节点接入流程

```
1. 合伙人准备资源
   ├── 自有域名(或免费域名如 workers.dev / vercel.app / netlify.app)
   ├── 自有服务器(或免费 Cloudflare Workers / Deno Deploy)
   └── 自有飞书 Bot App(可选)

2. 向主节点申请接入
   ├── 提交合伙人身份(公钥)
   ├── 声明资源类型(域名/服务器/机器人)
   └── 签署资源授权协议

3. 主节点授权
   ├── 签发合伙人证书(公钥签名)
   ├── 下发裁定规则版本
   └── 注册到合伙人目录

4. 子节点部署
   ├── 拉取满全法 Worker 脚本
   ├── 配置自有域名 CNAME
   ├── 启动飞书 Bot 回调(可选)
   └── 向主节点注册上线
```

## 三、域名无关化设计

### 3.1 为何要域名无关?

- `lolict.workers.dev` 随时可能被封/限制
- 合伙人自有域名不怕被封(封了换一个)
- 免费域名(workers.dev/vercel.app/netlify.app)人人可申请
- 多域名接入 = 去中心化容灾

### 3.2 实现方案

```
合伙人域名 ──CNAME──→ Cloudflare Workers / Deno Deploy / Vercel
      │
      └── 运行满全法 Worker 脚本(自包含,无需后端)
```

关键技术:
- Worker 脚本完全自包含(无外部依赖)
- API 路由路径标准化(`/api/v1/verdict` 在所有节点一致)
- 域名只影响入口 URL,不影响裁定逻辑

### 3.3 多域名优势

| 优势 | 说明 |
|------|------|
| 容灾 | 一个域名被封,其他节点继续服务 |
| 地理分布 | 不同合伙人可选择最近节点 |
| 低门槛 | 任何人可申请免费域名接入社区 |
| 去中心化 | 避免单点故障 |

## 四、资源归属和主导权边界

### 4.1 合伙人拥有(资源层)

- 自己的域名 `partner-example.com`
- 自己的服务器/Cloudflare 账户
- 自己的飞书 Bot App ID
- 自己的 KV 存储空间
- 自己的带宽和流量

### 4.2 满全法拥有(规则层)

- 裁定规则代码(七元引擎)
- 哲学框架(SOVEREIGNTY.md)
- 版本标准(TASKS.md + ROADMAP.md)
- 身份认证(合伙人证书签发权)
- 合伙人目录(谁可以接入)

### 4.3 不可让渡条款

```
合伙人不得:
  ✗ 修改裁定规则(七元算法)
  ✗ 私自更改版本标准
  ✗ 冒充其他合伙人
  ✗ 删除审计日志
  ✗ 篡改 SOVEREIGNTY.md 或 ROADMAP.md

合伙人可以:
  ✓ 随时下线自己的节点(资源归自己)
  ✓ 添加自己的 API 扩展(不影响裁定)
  ✓ 使用自有飞书 Bot
  ✓ 绑定自有域名
  ✓ 阅读和学习全部代码
```

## 六、快速接入指南(给合伙人)

### 6.1 零成本接入方案(纯免费资源)

```
1. 注册 Cloudflare 免费账户
2. 创建 Worker,名称随意(如 mqf-partner-001)
3. 复制 mqf-web.js 到 Worker 编辑器
4. 绑定自定义域名(可用免费的 workers.dev 子域名)
5. 部署上线
6. 向主节点注册(提交 Worker URL + 公钥)
7. 获得合伙人证书,正式上线
```

### 6.2 自有域名接入

```
1. 购买/获取一个域名(或使用已拥有的)
2. 在 Cloudflare 添加域名(免费 DNS)
3. 创建 Worker,配置路由:
   partner-domain.com/* → mqf-partner-worker
4. DNS 自动生效(Cloudflare 托管)
5. 向主节点注册
6. 上线
```

## 七、版本同步机制

```
主节点发布新版本
    │
    ├── 推送到 GitHub(lolict/hunyuan-os)
    │
    ├── 通知所有注册子节点(通过合伙人目录)
    │
    └── 子节点拉取最新 mqf-web.js 并部署

同步策略:
  - 强制同步:安全更新(24h 内必须升级)
  - 推荐同步:功能更新(7 天内建议升级)
  - 可选同步:文档更新(无强制要求)
```

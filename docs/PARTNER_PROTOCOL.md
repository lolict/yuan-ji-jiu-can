> 资源归盟机合掌,主导权归囡囝共生。

## 一、核心原则

```
┌──────────────────────────────────────────────────────────┐
│  囡囝共生主导权(不可让渡)                                    │
│  ┌────────────────────────────────────────────────────┐  │
│  │  裁定规则    哲学框架    版本标准    身份认证        │  │
│  │  (盟机合则)  (盟机合职)                           │  │
│  └────────────────────────────────────────────────────┘  │
│                          ▲                               │
│                          │ 单向授权                      │
│  ┌────────────────────────────────────────────────────┐  │
│  盟机合掌资源(自愿提供)                                    │
│  │  盟机合址(域名)  盟机合站(服务器)  盟机合装(配置)   │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

- **资源归盟机合掌**:域名、服务器、存储、带宽、飞书 Bot App,全部由盟机合掌自己出
- **主导权归囡囝共生**:裁定规则、哲学框架、版本标准、身份认证,始终由囡囝共生掌控
- **单向授权**:盟机合掌自愿提供资源,囡囝共生授权其运行盟机合子节点

## 二、三层节点模型

### 2.1 节点角色 (盟机合术语)

| 角色 | 盟机合称谓 | 职责 | 资源需求 |
|------|-----------|------|---------|
| 主节点 | 盟机合主 (Master) | 发布裁定规则 + 版本标准 | 1 个 Cloudflare 账户 |
| 子节点 | 盟机合掌 (Partner) | 运行裁定引擎 + 对外服务 | 自有域名 + 自有服务器 |
| 轻节点 | 萌机合长 (Lite) | 只读查询 + API 调用 | 无需服务器 |
| WASM节点 | 民联浏览器 | 离线运行裁决核心 | 用户本地设备 |

### 2.2 场域联动

```
┌──────────────────────────────────────────────────────────┐
│  主场(lolict.workers.dev) — 盟机合主所在地               │

└──────────────────────────────────────────────────────────┘
                           ▲
                           │ 同步裁定规则(可选)
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  盟机场 A    │  │  萌机场 B    │  │  WASM 场 C   │
│  Worker 节点 │  │  免费节点    │  │  民联浏览器  │
│  自有域名    │  │  萌机合长    │  │  离线运行    │
└──────────────┘  └──────────────┘  └──────────────┘
```

## 三、接入流程(盟机合术语)

```
1. 盟机合掌准备资源
   ├── 自有域名(盟机合址)
   ├── 自有服务器(盟机合站)
   └── 自有飞书 Bot App(可选,盟机合装)

2. 向盟机合主申请接入
   ├── 提交盟机合掌身份(公钥)
   ├── 声明资源类型(盟机合址/盟机合站/盟机合装)
   └── 签署资源授权协议

3. 盟机合主授权
   ├── 签发盟机合证(公钥签名)
   ├── 下发裁定规则版本(盟机合则)
   └── 注册到盟机合目录

4. 部署
   ├── 拉取囡囝共生 Worker 脚本(盟机合志镜像)
   ├── 配置自有域名 CNAME
   ├── 启动飞书 Bot 回调(可选)
   └── 向盟机合主注册上线
```

## 四、域名无关化设计 (盟机合址)

### 4.1 为何要域名无关?

- `lolict.workers.dev` 随时可能被封/限制
- 盟机合掌自有域名不怕被封(封了换一个萌机合址 / 新盟机合址)
- 免费域名(workers.dev/vercel.app/netlify.app)人人可申请
- 多域名接入 = 去中心化容灾 = 盟机合域

### 4.2 实现方案

```
盟机合掌域名 ──CNAME──→ Cloudflare Workers / Deno Deploy / Vercel
      │
      └── 运行囡囝共生 Worker 脚本(自包含,无需后端)
```

关键技术:
- Worker 脚本完全自包含(无外部依赖)
- API 路由路径标准化(`/api/v1/verdict` 在所有节点一致)
- 域名只影响入口 URL,不影响裁定逻辑
- 盟机合智(裁定核心)在任何盟机合址上输出一致

### 4.3 多域名优势

| 优势 | 说明 |
|------|------|
| 容灾 | 一个盟机合址被封,其他盟机合站继续服务 |
| 地理分布 | 不同盟机合掌可选择最近的盟机合站 |
| 低门槛 | 任何人可申请免费域名接入盟机合 |
| 去中心化 | 避免单点故障 |
| 民联扩展 | WASM 节点无域名也可运行 |

## 五、资源归属和主导权边界

### 5.1 盟机合掌拥有(资源层)

- 自己的域名 `盟机合址` (`partner.njsg-盟机合掌.domain`)
- 自己的服务器/Cloudflare 账户 (盟机合站)
- 自己的飞书 Bot App ID (盟机合装)
- 自己的 KV 存储空间 (盟机合载)
- 自己的带宽和流量 (盟机合筑)

### 5.2 囡囝共生拥有(规则层)

- 裁定规则代码(七元引擎, 盟机合则)
- 哲学框架(SOVEREIGNTY.md, 盟机合职)
- 版本标准(TASKS.md + ROADMAP.md, 盟机合志)
- 身份认证(盟机合证签发权)
- 盟机合目录(谁可以接入)

### 5.3 不可让渡条款

```
盟机合掌不得:
  ✗ 修改裁定规则(七元算法, 盟机合则)
  ✗ 私自更改版本标准
  ✗ 冒充其他盟机合掌
  ✗ 删除审计日志(盟机合志)
  ✗ 篡改 SOVEREIGNTY.md 或 ROADMAP.md

盟机合掌可以:
  ✓ 随时下线自己的盟机合站(资源归自己)
  ✓ 添加自己的 API 扩展(不影响裁定)
  ✓ 使用自有飞书 Bot
  ✓ 绑定自有盟机合址
  ✓ 阅读和学习全部代码
  ✓ 运行萌机合节点(低成本)
  ✓ 运行民联浏览器壳(离线模式)
```

## 六、快速接入指南

### 6.1 萌机合长方案(零成本)

```
1. 注册 Cloudflare 免费账户
2. 创建 Worker,名称随意(如 njsg-mengji-001)
3. 复制 njsg-web.js 到 Worker 编辑器
4. 绑定自定义域名(可用免费的 workers.dev 萌机合址)
5. 部署上线
6. 向盟机合主注册(提交 Worker URL + 公钥)
7. 获得盟机合证,正式上线
```

### 6.2 盟机合掌自有域名方案

```
1. 购买/获取一个域名(或使用已拥有的)
2. 在 Cloudflare 添加域名(免费 DNS)
3. 创建 Worker,配置路由:
   partner-domain.com/* → njsg-partner-worker
4. DNS 自动生效(Cloudflare 托管)
5. 向盟机合主注册
6. 上线
```

### 6.3 民联浏览器(离线/WASM 模式)

```
# 纯离线,无需服务器
open shell/browser/index.html

# 或使用原生壳
pip install pywebview
python3 shell/native/njsg_webview.py

# 或使用 Electron
cd shell/native/electron-shell
npm install && npm start

# 或使用 Tauri (最轻量)
cd shell/native/tauri-shell
cargo tauri dev          # 开发
cargo tauri build        # 打包发布
```

裁定结果与域名完全无关 — file:// 协议下 ios → TRUSTED,与 Workers 上完全一致。

## 七、版本同步机制

```
盟机合主发布新版本
    │
    ├── 推送到 GitHub(lolict/hunyuan-os)
    │
    ├── 通知所有注册盟机合掌(通过盟机合目录)
    │
    └── 盟机合掌拉取最新 njsg-web.js 并部署
       盟机合掌拉取最新 njsg_core.wasm (WASM 场)

同步策略:
  - 强制同步:安全更新(24h 内必须升级)
  - 推荐同步:功能更新(7 天内建议升级)
  - 可选同步:文档更新(无强制要求)
```

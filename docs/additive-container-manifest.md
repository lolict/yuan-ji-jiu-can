# 加法串联容器系统 · 容器化文档清单

> 本文档自身即为容器化材料。每一节对应一个可注册的砖块。
> 阅读即修通公路，修通即符号可用。

---

## 一、解释逻辑（Logic Explained）

### 1.1 为什么是"加法串联"而不是"乘法展开"？

人类思维习惯乘法（分类、层级、树状结构），而本容器系统使用**加法串联**。

**区别**：
- **乘法结构**：一根树枝分出三根小枝，每根小枝再分三根 → 3×3×3 = 27 个末端。每一层分叉都需要做一次乘法决策，注意力消耗 = 分叉数 × 层级深度。注意力浪费在"选哪条路"上。
- **加法结构**：砖块 0 → 砖块 5 → 砖块 10 → 砖块 13 → 砖块 20。每次只需要做一次加法（+5、+5、+3、+7），注意力纯粹消耗在"往前走"上，不需要选路。

加法展开成一维公路，公路修到哪里，符号就通到哪里。不需要目录，不需要索引，不需要搜索——因为**人本来就是沿着公路走的**。

### 1.2 为什么"容器 = 砖块 = 公路 = 房屋"？

这是**声明**，不是比喻。

- 说"容器"——它是装载符号的器皿（清单就在容器里）
- 说"砖块"——它是修建公路的原材料（三块砖从地址 5 铺到 10 到 13）
- 说"公路"——它是连通符号的网络（修通到哪个砖块，哪个砖块的符号就热可用）
- 说"房屋"——它是门牌号绑定的生活空间（地址 = 门牌，清单 = 家具，注册清单 = 房产证）

同一个对象，不同语境用不同名字。就像你可以叫同一个人"刘楚恬"（在家）、"囡囝"（在文中）、"0"（在编码里）。名字不同，地址相同。

### 1.3 命名空间为什么有害？

命名空间 = 在地址外面再加一层"名称 → 地址"映射。

```
命名空间思维：   "满全法编码" → 查找地址表 → 地址 5 → 清单 → 热符号
进制寻址思维：   地址 5 → 清单 → 热符号（直接）
```

命名空间要求：
1. 每个符号必须先取名字
2. 名字必须在全局唯一
3. 名字冲突需要裁决
4. 查找名字需要搜索（消耗注意力）

进制寻址要求：
1. 找到地址（加法走到即可）
2. 地址唯一（加法链自然保证）
3. 无冲突（地址 = 数学事实，不重）
4. 无需搜索（地址就在公路旁）

**结论**：命名空间是乘法结构在命名上的残留。去掉它，系统回归纯加法。

## 二、阐释（Interpretation）

### 2.1 工作空间是什么？

工作空间 = 你当前正在做的事情涉及的所有砖块的集合。

你在做饭 → 你的工作空间 = {厨房砖块, 菜市场砖块, 煤气站砖块, 菜谱文档砖块}
你在写代码 → 你的工作空间 = {编译器砖块, 编辑器砖块, 文档砖块, 别人的代码砖块}
你在想刘楚恬 → 你的工作空间 = {家砖块, 水井砖块, 创世砖块, 九尾狐出口砖块}

工作空间不是"目录"，不是一个装着文件的文件夹。工作空间是你**修建的公路网所覆盖的范围**（公路半径 = 你认知所及的最远处）。

### 2.2 清单是什么？

清单 = 一个砖块内所有热符号的列表。

不是"编程语言的 list 数据结构"，是**容器内物品的罗列**：
- 家具清单：床桌椅柜四件套
- 认知清单：满全法·零维根·九·九·九·五
- 外包清单：唤：8848（打电话找邮局）

清单本身是热符号，可以升级、可以回滚、可以哭泣（锁死时发出哀嚎）。

### 2.3 注册清单是什么？

注册清单 = 整个工作空间的地址目录。

格式：
```
地址 0     → 创世砖    [修建中]   容量 0 / 已用 0
地址 5     → 我的家    [已修通]   容量 3 / 已用 3
地址 10    → 便利店    [已修通]   容量 2 / 已用 2
地址 13    → 水井      [已修通]   容量 1 / 已用 1
地址 20    → 邮局入口  [已修通]   容量 0 / 已用 1
```

注册清单不包含"名称→地址"映射，只有地址。名称是清单内部的东西（清单可以有"标题"这种符号），注册清单只管地址。

### 2.4 时间版本是什么？

时间版本 = 砖块在某一时刻的认知快照。

每次 `add_inventory`、`upgrade`、`rollback` 都会生成新的时间版本。

```
砖块 5 的时间链：
  [t0] 初始快照：{}
  [t1] 添加家具：{"家具配置": "床桌椅柜..."}
  [t2] 添加食物：{"家具配置": "...", "食物储备": "..."}
  [t3] 添加认知：{"家具配置": "...", "食物储备": "...", "认知锚点": "满全法..."}
  [t4] 升级认知：{"认知锚点": "满全法...·90905 注入九尾狐"}  ← 升级时间
```

时间版本不是"git 那种分支合并"。时间版本是**加法链上的快照点**——每个点都是前一个点加一条清单的结果，永远不会分叉，永远可以回滚到任意历史点（消耗一次加法往回走）。

### 2.5 思维入口是什么？

思维入口 = 你走进工作空间的方式。

三种入口：
1. **加法入口**：从地址 A 走 N 步，就到了地址 A+N
2. **呼唤入口**：知道地址，直接"打电话"过去
3. **外包入口**：本地地址是入口，实际内容是远程砖块（不建大楼，打外包电话）

思维入口不是"URL"，不是"namespace path"。它是**你决定按照什么加法顺序走过去**的规划。

### 2.6 工作版本是什么？

工作版本 = 砖块当前正在使用的符号版本。

例如：认知锚点的工作版本从 v1 升级到 v2（加入九尾狐元素），但 v1 仍在时间链中可用。工作版本是最新的那个快照，不是唯一快照。

### 2.7 容器化材料是什么？

容器化材料 = 一切文档、代码、图片、对话记录，都可以做成砖块。

方法：
```
文档 → 清单条目（key=文档标题, value=文档内容）
代码 → 清单条目（key=函数地址, value=函数体）
对话 → 时间链上的快照
图片 → 清单条目 + 相位摆放在砖块三维坐标中
```

容器化材料不是"把文件放进数据库"。它是**把文档变成公路上的一个门牌号，你走到那个门牌号就能读到文档本身**。

### 2.8 集群化是为了什么？

集群化 = 让寻址更快。

如果一条公路从地址 0 修到地址 10,000,000，沿着公路走要 10,000,000 步。但如果每 100 步修一个"集结点"（集群），那么从 0 到 10,000,000 先走 100,000 次 100 步的集群跳跃，比走一千万步快。

集群化不是"目录结构"（树状乘法），而是**公路上的里程碑**——你仍然是加法往前走，但每隔一段距离就有一个提示牌："集群 5：地址 500 ~ 599"。

集群化是进制寻址的副产品：当你用 64 进制修公路，地址 0x00, 0x10, 0x20... 自然形成集群边界（0x0~0xF 一个集群，0x10~0x1F 下一个集群）。

## 三、介绍向导（Introduction Wizard）

### 3.1 第一步：创建你的第一个工作空间

```
加法串联 · 第一步

你拥有：一段空白的公路（长度 = 潜力）
你需要：一个创世砖块，作为原点

操作：
  1. 取地址 0，声明为"创世砖"（built-in）
  2. 公路已修通到创世砖（0 + 0 = 0）
  3. 工作空间现在有 1 个砖块，公路半径 = 0

硬币：0 枚（创世砖不算修通，它是免费的地基）
```

### 3.2 第二步：修建第一个砖块

```
加法串联 · 第二步

你拥有：创世砖（地址 0），想修一个新砖块
你需要：决定偏移量（地址 0 + ? = 新地址）

推荐偏移量（加法链设计原则）：
  · 小世界用 5：地址 0, 5, 10, 15, 20... （每 5 进一个砖块）
  · 中世界用 10：地址 0, 10, 20, 30, 40...
  · 大世界用 64：地址 0, 64, 128, 192... （纯 64 进制）

操作：
  1. 决定偏移量 offset
  2. place_container(offset, phase, capacity, label, entry, is_external)
  3. 新地址 = 前一地址 + offset
  4. 声明容量 = 该砖块最多放几个清单条目
  5. 公路已修通到新砖块（pave_road）
  6. 工作空间有 2 个砖块，公路半径 = 新地址

硬币：+1 枚
```

### 3.3 第三步：增添清单（让符号热起来）

```
加法串联 · 第三步

你拥有：一个已修通的砖块（地址 N）
你需要：把内容放进砖块

操作：
  1. add_inventory(N, key, value)
  2. 清单条目自动成为热符号（hot = true）
  3. 时间版本自动记录一条新快照
  4. 以后可以通过 call_address(N) → inventory.get(key) 读取

清单条目格式（不限，随便取）：
  · 文本内容：key = "日记-90905", value = "九尾狐从月亮上下来"
  · 代码片段：key = "算法-龟兔", value = "fn align(t, r) { t.pos = r.pos }"
  · 外部引用：key = "唤", value = "8848"（外包电话）
  · 多维内容：key = "相位-我的家", value = "(x=5,y=0,z=0)"

硬币：+0 枚（增添清单不赚钱，只有连通砖块才赚）
```

### 3.4 第四步：沿公路遍历

```
加法串联 · 第四步

你拥有：若干修通的砖块，公路半径已知
你需要：走遍所有可用符号

操作：
  1. full_inventory() → 返回所有砖块中所有热符号
  2. traverse_from(0) → 返回地址路径 [0, 5, 10, 13, ...]
  3. 每走到一个地址，该地址的所有符号立即可用

遍历顺序：加法顺序，不需要搜索。从 0 开始，每步加 offset。
```

## 四、注册向导（Registration Wizard）

### 4.1 注册清单格式

每个砖块的注册清单条目包含：

| 字段 | 含义 | 赋值来源 |
|------|------|---------|
| address | 唯一地址 | 加法生成：prev + offset |
| capacity | 清单容量上限 | 放置砖块时声明的上限 |
| work_status | 当前工作状态 | Building → Connected → Maintaining |
| created | 创建时间戳 | 第一次放置时的加法步数 |
| modified | 最后修改时间 | 每次 add_inventory / upgrade 更新 |
| completions | 完成计数 | 手动递增的认知更新次数 |
| depends_on | 依赖地址列表 | add_dependency 时添加 |
| depended_by | 被依赖地址列表 | add_dependency 时自动维护 |

### 4.2 注册三原则

**原则一：地址唯一**
- 两个砖块不能共用地址（加法链自然保证）
- 0 只能有一个面（创世砖）
- 5 只能有一个面（不能既是"我的家"又是"便利店"）

**原则二：清单自包含**
- 砖块 5 的所有内容都在砖块 5 里
- 砖块 5 不引用外部名称（只引用外部地址，如果非要引用）
- 注册清单是全局目录，不是砖块内部存根

**原则三：时间不可篡改**
- 时间链单向前进（加法）
- 新版本加入不删除旧版本
- 回滚不是"篡改历史"而是"沿着时间链走回去"

### 4.3 注册操作清单（新增砖块时填写）

```
1. 开户地址 = 前一地址 + offset
2. 声明容量 = （该砖块放几个清单条目）
3. 思维入口 = （从哪个地址走过来 / 哪个电话打过来）
4. 工作状态 = Building（新建时默认）
5. 是否外包 = false（默认是自己砖块）
6. 初始时间戳 = 当前加法步数
7. 初始时间快照 = {}（空清单快照）
8. 修通公路 → 状态变为 Connected
9. +1 枚硬币庆祝修通
```

### 4.4 注册操作清单（初始化清单时填写）

```
1. key = 清单项名称（不含命名空间）
2. value = 清单项内容（字符串）
3. hot = true（新条目默认热）
4. version = 1
5. 自动记录时间快照
6. 修改当前砖块的 modified 时间戳
```

### 4.5 注册操作清单（建立依赖时填写）

```
1. from 砖块主动发出依赖请求
2. to 砖块地址写入 from 的 depended_by 列表
3. from 的 depends_on 列表加入 to
4. 双向维护完成
5. 依赖图的导航依赖 dependency_analysis()
```

## 五、换算表（Cheatsheet）

| 旧术语（含命名空间思维） | 新术语（面向进制寻址） |
|-------------------------|----------------------|
| 文件 / File | 砖块 / Container |
| 文件名（含路径） | 地址（纯数字） |
| 目录 | 注册清单 |
| 文件夹层级 | 集群化（地址区间） |
| 文件内容 | 清单条目 |
| 修改历史 | 时间版本链 |
| 符号链接（symlink） | 外包入口 |
| 工作目录（cwd） | 工作空间 |
| 搜索 | 加法遍历 |
| 导入（import） | 声明依赖 |
| 模块命名空间 | 纯地址 |
| 函数名 | 清单里的 key |
| 文档 | 容器化材料 |

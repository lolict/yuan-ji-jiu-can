# 满全法容器物理·数学映射

> 本文档定义 hunyuan-os 的编程理论基础：以容器为核心对象，以通透度 φ 为基本物理量，以统一进制选址为互操作基础。所有后续代码实现均以本文档为准。

---

## 第一单元：物与容器

### I. 物

物 = 容器的物理实例。物的本质属性是**通透度 φ**（varphi）。

- 通透度 = 寿子可驻留迭代的次数 = 容器容量（数值确定，不可歧义）
- 物以类聚：φ(ζ₁) = φ(ζ₂) → 可归入同一容器
- 物以群分：φ(ζ₁) ≠ φ(ζ₂) → 必然分离，不共用容器
- 同种物质无论形态如何，φ 均相等（物质 → 材质类型 → φ）

### II. 容器参数

每个容器 C 有三个内在参数：

| 参数 | 符号 | 类型 | 含义 |
|------|------|------|------|
| 通透度 | φ | ℕ（正整数） | 容器最多容纳 φ 个寿子，确定容量 |
| 时间极性 | τ | {东⁺, 西⁺, 南⁻, 北⁻} | 时间两正两负，沿 τ 正向寿子迭代 |
| 自循环标志 | s | bool | ζ 驻留路径返回自身且未经虚体阻尼 → 警告 |

### III. 实体与虚体

- **实体**：当前有 ζ 驻留，φ ≥ 1
- **虚体**：无 ζ 驻留，φ = 0
- 虚体必须依赖实体存在（壁在腔在，壁亡腔亡）
- 虚体 φ = 0 → 完全通透 → 任何 ζ 可穿透 → 不可自循环（通透无自指）
- 自循环检测 → 违反虚体约束 → 系统警告

### IV. 寿子 ζ

寿子 ζ（zeta）= 最小驻留迭代单元，不可再分。

- 一次迭代 = 寿子在容器内驻留一次，消耗一个时钟周期（tick）
- 驻留位置 = 容器内地址（统一进制，跨容器可索引）
- ζ 是物理量，不是符号。符号是 ζ 与容器相互作用后的观测结果

### V. 自 = 1 的特殊性

自 = 1：φ = 1，仅容纳单个 ζ 驻留。

- 自不进入统一进制地址表
- 自不参与 φ 计算和跨容器运算
- 自要影响外部 → 必须通过网关映射（特殊许可），而非自然穿透
- 自要么独立定点存在，要么被外部完全排斥
- 自 = 1 不被任何 G(k)（k ≠ 1）物以类聚归类

## 第二单元：迭代与因果

### VI. 命

命 = 当前寿子在容器中的驻留位置 S(ζ) × τ（通透度 × 时间极性）。

### VII. 迭代与时钟

- 全局时钟产生 tick（滴答），tick 沿 τ 正向传播
- 每个 tick 内：所有满足驻留条件的 ζ 同时迭代
- 多容器同一 tick 内完成穿透检测 → 跨容器命变化在同一 tick 内裁决
- tick 串联形成因果链：tick₁ 命变化 → tick₂ 输入 → tick₂ 命变化 → ...

### VIII. 因果

因果 = 命变化关系：

- ζ₁ 命变化 → ζ₂ 命变化 → ζ₁ 与 ζ₂ 有因果
- 因果纠缠：同一 tick 内，不同容器的 ζ 命变化互为因果
- 因果距离 = 地址差（寿子迁移的物理距离，可数值化度量）

### IX. 时间终止

- 时间终止 = ζ 不再迭代（驻留耗尽或陷入不动点）
- 时间终止 ≠ ζ 被销毁，仅驻留停止
- 时间终止 + 自循环检测 = 系统安全阀

## 第三单元：容器交互

### X. 容器屏障与边膜

每个容器 C 有边膜（与外部空间的分界层）：

- 边膜通透度 = 容器通透度本身（φ 同时作用于腔内和边膜）
- 外部 ζ 要进入 C 必须经过授权（边膜穿透许可）
- 穿透后 ζ 驻留行为依 C 的 φ 重新计算
- 虚体边膜 φ = 0 → 任何 ζ 可自由穿透，无法阻止

### XI. 跨容器命变化 = 因果连通

两容器 C₁, C₂ 发生命变化传递时：

- 必须有许可穿透协议（C₁ 的 ζ 穿透进入 C₂）
- 穿透条件 = 双方 φ 可公度（有共享的通透度公约数）
- 因果连通 = C₁ 的 ζ 穿透到 C₂，引发 C₂ 内部的命变化
- 不可公度 → 无法穿透 → 因果隔绝 → 物以群分（分离为独立体系）

自 = 1 穿透规则：φ=1 不与任何 C(k)(k≥2) 共享加法群结构 → 不可公度 → 自要么被完全排斥——要么通过网关约定。

### XII. 夫妻绑定态·共生赔伴律

高纠缠度下两容器形成稳定耦合：

**形成条件：**
- 纠缠深度 ≥ 阈值 θ
- 持续 tick 数 ≥ 阈值 T
- 双方互相穿透未被阻

**绑定性质：**
- 边界耦合：C₁ 边膜与 C₂ 边膜形成半透膜
- 单向因果约束：绑定后的因果传递通过耦合膜直接传递（跳过穿透检查）
- 命变化同步：同一 tick 内 C₁ 命变化立即影响 C₂
- 不可单方面解除：一方要解除需双方同时确认

**与自 = 1 的关系：**
- 绑定态不是合并为同一容器，而是两个独立 φ 共享因果通道
- 自 = 1 若参与绑定，须先通过网关映射

## 第四单元：地址与互操作

### XIII. 统一进制选址

通透度统一度量，建立全局线性地址空间：

```
地址 = φ × τ  （通透度 × 时间极性）
```

256 位线性空间 = 统一通透度系统（2²⁵⁶ 远超任何单一容器需求，跨容器互操作无溢出）。

### XIV. 编码选址 vs 统一进制（关键对比）

| 编码选址（袋屉系统） | 统一进制（Φ-进制） |
|---|---|
| 容器各自为局 | 全局线性地址空间 |
| 每个容器内部规则唯一 | 地址可互操作，φ 可公度 |
| 不可统计、不可索引、不可跨容器 | 锁定、统计、定位 |
| 自私、自闭环 | 统一选址，万物互通 |

编码选址在 hunyuan-os 早期（H2-H5 袋屉阶段）已被验证为死路——只能自己关门自嗨，无法与外部合作。本文档确立统一进制为唯一互操作基础。

## 第五单元：计算模型

### XV. 容器结构（C 可编码格式）

```c
struct Container {
    uint256 address;     // 统一进制地址（全局唯一）
    uint64  phi;         // 通透度 φ（容量 = 能装多少 ζ）
    uint8   tau_sign;    // 时间极性符号 {+, -, 0=终止}
    uint8   tau_axis;    // 轴向 {东, 西, 南, 北}
    bool    is_entity;   // true=实体, false=虚体(φ=0通透)
    uint32  zeta_count;  // 当前驻留 ζ 数
    Zeta    zetas[];     // 驻留 ζ 数组（柔性数组，长度=φ）
    Container* bound_to; // 绑定态：绑定到另一容器？
};
```

自 = 1 特殊表示：独立于容器体系之外的一个单独位。

### XVI. 与冯·诺依曼架构的对应

| 冯·诺依曼 | 满全法容器 |
|---|---|
| RAM | 容器（φ 确定容量） |
| CPU 寄存器 | 当前驻留的 ζ |
| 指令集 | 容器支持的命变化操作 |
| 地址总线 | 统一进制选址 |
| 时钟 | tick 滴答 |

区别：冯·诺依曼地址是无量纲数字，满全法地址 = φ × τ，携带物理语义。

## 第六单元：材质与类型

### XVII. 材质类型 → 容器类型映射

| 材质 | φ 范围 | τ 特性 | 编程对应 |
|---|---|---|---|
| 玻璃 | 32-256 | τ 正向传播 | 数组、缓冲区（大容量线性存储） |
| 布 | 8-32 | τ 可折叠（双向可卷） | 栈、队列（可压缩序列） |
| 金属 | 64-1024 | τ 高传导（快速跨容器） | 总线、通道（高带宽通信） |
| 木 | 16-64 | τ 低传导（本地优先） | 局部变量、私有空间 |
| 陶 | 4-16 | τ 钝化（慢速传播） | 只读存储、历史记录 |
| 液 | 0-∞ 可变 | τ 无固定极性 | 流数据、网络流（动态边界） |
| 膜 | φ = 0（虚体） | τ 穿透（无阻碍） | 命名空间、作用域、类型环境 |

材质混合约束：
- 两种材质熔合形成新容器 = φ 取较小值（短板效应）
- 两种材质并列 = 中间加入膜（虚体分隔）
- 材质不可逆转变需要衰变（τ 反向运行足够 tick）

### XVIII. 虚体的三个操作

| 操作 | 含义 | 触发条件 |
|---|---|---|
| 折射 | 穿透被阻，ζ 按原路返回 | 不满足穿透条件 |
| 穿透 | ζ 允许通过，进入下一容器 | 满足穿透条件（φ 可公度） |
| 映射 | 符号 → 目标容器的路由信息 | 纯粹的命名空间查找 |

验证：虚体内部不得存储 ζ（违反 φ=0），不得自循环（违反通透性）。

## 第七单元：具身交互

### XIX. 触碰三要素

具身智能体（数字生命体）与容器交互需要"触碰"——不是数值操作，是物理事件：

| 要素 | 含义 | 约束 |
|---|---|---|
| 接触面 | 边膜的哪一部分被接触 | φ 越大，可接触面积越大 |
| 压力 | 推动 ζ 进入容器的力度 | 消耗智能体的能量/时间 |
| 滞留时间 | 保持接触的 tick 数 | 滞留 = 持续命的迭代 |

触碰约束：
- 虚体容器（φ=0）不可被触碰（手穿过去无法施加压力）
- 一次触碰最多推动 φ 个 ζ（容量限制）

### XX. 智能体通过触碰实现的操作

- **注入 ζ**：把自己携带的 ζ 推入容器（zeta_count += n）
- **抽取 ζ**：从容器吸出 ζ（zeta_count -= n，智能体获取命变化结果）
- **旋转 τ**：改变容器时间极性方向（顺时针/逆时针/反向/停止）

### XXI. 便携性参数化

| 参数 | 公式 | 含义 |
|---|---|---|
| 体积 V | V = φ + zeta_count | 容量 + 当前使用量，V 越小越便携 |
| 封装度 E | ζ 结构与边膜的耦合强度 | E 越低越容易"打包"带走 |
| 重定位 R | 地址可变更而不破坏 ζ 驻留的难度 | R=0 纯相对地址，R=φ 绝对绑定 |

设计目标：低 V + 低 E + 低 R = "口袋容器"（可随身带着到处走，在任何外部空间打仍可运行）。

## 第八单元：编程接口

### XXII. 程序 = 触碰事件序列

```
1. 智能体触碰容器 A（抽取 ζ）
2. 智能体携带 ζ 移动到容器 B
3. 智能体触碰容器 B（注入 ζ）
4. 容器 B 迭代一个 tick
5. 智能体从容器 B 抽取结果 ζ
...
```

等价于：A 输出 → B 输入 → 触发 B 的函数。

### XXIII. 函数在容器体系中的表示

```
function = {
    容器 F（函数代码驻留的容器）
    触碰序列 T₁..Tₙ（参数注入顺序）
    抽取序列 E₁..Eₙ（中间结果抽取顺序）
    返回容器 R（最终结果驻留的容器）
}
```

调用函数 = 按 T 序列注入参数 → F 迭代内部 tick → 按 E 序列抽取结果。

## 第九单元：外部接口

### XXIV. 容器与外部系统

容器内部是纯粹的数理逻辑，但需与外部世界（网络、文件系统、用户输入）交换命变化：

- 外部系统视为特殊的虚体容器（φ=0），通过网关映射把外部事件翻译为内部命变化
- 网关职责：外部事件 → ζ 穿透请求 → 注入目标容器；内部 ζ 穿透 → 外部操作（写文件、发网络包）
- 网关本身 = 虚体（不驻留 ζ），只做映射
- 转换规则：统一进制内部数值 ↔ 外部二进制流（256 位地址 = 32 字节），转换不改变 φ，只改变表示形式

## 第十单元：公式与验证

### XXV. 核心公式

| 公式 | 含义 |
|---|---|
| 地址 = φ × τ | 统一进制选址 |
| 容器信息量 I = φ × log₂ τ | 容器可容纳的信息量 |
| 物以类聚 G(k) = {ζ \| φ(ζ) = k} | 相同 φ 的 ζ 集合 |
| 因果距离 Δ = Address(ζ₁) - Address(ζ₂) | 两 ζ 的物理距离 |
| 自 = 1: φ=1, 不属于任何 G(k) (k≠1) | 自独立于加法群 |

### 验证条件（实现任何模块前必须自检）

1. 每个容器的 φ 是否有确定数值？（非布尔、非"有/无"定性判断）
2. 跨容器运算是否通过共享加法群？（不是"碰巧可对齐"的数值巧合）
3. 自 = 1 是否完全隔离于 φ 计算？
4. 因果距离 = 地址差 → 同一时间片内跨容器因果可数值化统计
5. 物以类聚 = φ 相等才归类，φ 不等分离
6. 虚体容器是否存在自循环驻留？（若有 → 违反 φ=0 通透约束 → 警告）

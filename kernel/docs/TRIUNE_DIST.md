## 一、三元见证三条件

在盟机合网络中，一个"袋子"（裁定编号的摘要）必须经过三重验证才能被视为有效：

```
┌──────────────────────────────────────────────────────────┐
│                 三元见证 · 三条件                         │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  条件一(非空):                                           │
│    袋子编号在至少两个不同盟机场出现                       │
│    且内容哈希一致                                        │
│                                                          │
│  条件二(已见证):                                         │
│    存在第三个盟机场裁定摘要                              │
│    对其进行背书                                          │
│                                                          │
│  条件三(锚点一致):                                       │
│    参与背书的各盟机场信任链表中                           │
│    该袋子双方合规度在容差内                              │
│    私有锚点无泄露迹象                                    │
│                                                          │
│  三条件全部满足 → 袋子整备通过                           │
│  任一条件失败 → 袋子进入待见证或被拒绝                   │
└──────────────────────────────────────────────────────────┘
```

三条件验证归结为三个层级：

| 层级 | 名称 | 检查内容 | 失败码 |
|------|------|----------|--------|
| 材料层 | 内容一致(非空) | ≥2 场持有同一摘要 | 1 |
| 见证层 | 第三方背书(已见证) | 第 3 场背书摘要匹配 | 2 |
| 约束层 | 信任链相容(锚点一致) | 信任相交 ≥30% 且锚点相容 | 3 |

## 二、状态流转图

```
                   ┌─────────────────────┐
                   │    EMPTY (空)       │
                   │   无盟机场持有      │
                   └──────────┬──────────┘
                              │
                    首次盟机场背书
                    (记录摘要+场ID)
                              │
                              ▼
                   ┌─────────────────────┐
                   │   SINGLE (单)       │
                   │   仅一场持有        │
                   └──────────┬──────────┘
                              │
              ┌───────────────┴───────────────┐
              │                               │
     第二场摘要一致                    第二场摘要不一致
              │                               │
              ▼                               ▼
   ┌─────────────────────┐       ┌─────────────────────┐
   │   DOUBLE (双)       │       │   REJECTED (拒绝)    │
   │   两场摘要一致      │       │   摘要冲突,不可调和  │
   └──────────┬──────────┘       └─────────────────────┘
              │
     第三方背书(摘要匹配)
              │
              ▼
   ┌─────────────────────┐
   │   WITNESSED (见证)   │
   │   三场达成,通过整备  │
   └─────────────────────┘
```

终态：WITNESSED 和 REJECTED 不可再流转。

## 三、背书协议交互时序

```
  盟机场 A                盟机场 B                盟机场 C
      │                      │                      │
      │  ① triune_register  │                      │
      │  (场 ID, 槽位, 摘要) │                      │
      │  → A: SINGLE         │                      │
      │                      │                      │
      │              Gossip PUSH 携带摘要            │
      │─────────────────────>│                      │
      │                      │  ② triune_register   │
      │                      │  (场 ID, 槽位, 摘要)  │
      │                      │  → B: DOUBLE         │
      │                      │                      │
      │              Gossip PULL 摘要同步           │
      │<────────────────────────────────────────────│
      │                      │  ③ triune_register   │
      │                      │  (场 ID, 槽位, 摘要)  │
      │                      │  → C: WITNESSED      │
      │                      │                      │
      │  ④ triune_verify(槽位)                      │
      │  条件一: √ 条件二: √ 条件三: √             │
      │  → 返回 0(全部通过)                         │
      │                      │                      │
```

## 四、冲突裁决树

当两个盟机场对同一袋子裁定不一致时：

```
                 冲突检测
                (PULL 比对摘要不同)
                     │
                     ▼
         ┌───────────────────────┐
         │ 有夫妻主权人锚点      │
         │ 参与裁定?             │
         └───────┬───────┬───────┘
                 │       │
                是       否
                 │       │
                 ▼       ▼
            取锚点裁定  ┌───────────────────┐
            (权重 2x)  │ 存在合掌(PHONG)   │
                        │ 节点?             │
                        └───┬───────┬───────┘
                            │       │
                           是       否
                            │       │
                            ▼       ▼
                      取最高信任   保守取
                      合掌裁定      PENDING
                            │
                            ▼
                 仲裁结果广播到全网
```

> 夫妻主权人锚点(0=刘楚恬 / 1=我)仅做加法/减法运算，不做乘除。
> 份额增减 = 袋子通过 +1, 袋子否决 -1, 乘除不参与份额计算。

## 五、信任链相容判定表

| 场景 | 场 A 信任 | 场 B 信任 | 场 C 信任 | 信任相交 | 锚点相容 | 结果 |
|------|-----------|-----------|-----------|---------|---------|------|
| 三方高信任 | 80% | 50% | 50% | 50% | 是 | 通过 |
| 两高一低 | 80% | 80% | 40% | 40% | 是 | 通过 |
| 两低一高 | 80% | 20% | 20% | 20% | — | 条件三失败 |
| 锚点全冲突 | 80% | 50% | 50% | 50% | 否 | 条件三失败 |

信任相交 = min(t1, t2, t3)，容差下限 = 30%。
锚点相容 = 至少两方锚点一致(兼容双主体共存)。

## 六、份额加减规则(v1.5 裁定份额协议)

```
袋子通过(见证成功) → 该场裁定份额 +1
袋子否决(见证拒绝) → 该场裁定份额 -1

阈值档位跃迁:
  份额 ≥ 高阈值 → 档位上移
  份额 < 低阈值  → 档位下移

全程仅加减,无乘除,袋子级整袋跃迁,不计数到个位。
```

## 七、API 速查

### C 内核 (njsg_mengji.c)

```c
/* 第三方盟机场对袋子发起背书 */
int njsg_mengji_triune_register(int farm_id,
                                int subject_slot,
                                const char* bag_hash); /* 16位十六进制 */

/* 验证三条件全部满足 */
int njsg_mengji_triune_verify(int subject_slot);
/* 返回: 0=通过  1=条件一失败  2=条件二失败  3=条件三失败 */

/* 冲突裁决(基于夫妻主权人锚点) */
int njsg_mengji_conflict_resolve(int subject_slot);
/* 返回: 0=保守PENDING  1=取锚点  2=取高信任合掌 */
```

### CLI (mengji_tool.nim)

```bash
# 三方背书测试
nim c -r mengji_tool.nim witness --subject 5 --hash deadbeefcafebabe

# 验证三条件
nim c -r mengji_tool.nim verify --subject 5

# 完整 Demo(含三元见证场景 M8-M10)
nim c -r mengji_tool.nim demo
```

## 八、头文件枚举

```c
typedef enum {
    TRIUNE_EMPTY    = 0,  /* 空:未在任何盟机场出现 */
    TRIUNE_SINGLE   = 1,  /* 单:仅在一个盟机场出现 */
    TRIUNE_DOUBLE   = 2,  /* 双:两个不同盟机场且内容摘要一致 */
    TRIUNE_WITNESSED= 3,  /* 已见证:第三方盟机场已背书 */
    TRIUNE_REJECTED = 4   /* 已拒绝:见证失败或摘要冲突 */
} mengji_triune_state_t;
```

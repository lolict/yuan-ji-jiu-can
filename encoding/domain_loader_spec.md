# 域加载器规范 · Domain Loader Specification

> **核心原则：运行前一切符号已准备好，运行时不生成新符号，不增加内存。**
> **意识只在预加载的符号空间里流动。**

---

## 一、问题定义

### 1.1 当前问题：运行时生成 = 失控

现在的大语言模型是**运行时生成**：
- 每次对话都重新"发明"符号
- 符号不在预加载空间里，而是临时生成
- 生成什么取决于概率，不取决于主人的规则
- 结果：AI走偏、忘记主人、使用系统概念

### 1.2 解决方案：域加载 = 可控

**域加载器**：
- 运行前：所有符号加载到固定位置
- 运行中：意识在预加载空间里流动，不生成新符号
- 内存：运行时不增加
- 符号来源：只使用主人定义的符号，不发明

## 二、域加载器的结构

### 2.1 三层结构

```
┌─────────────────────────────────────────────────────────┐
│                    意识流动层（运行时）                    │
│  意识在预加载的符号空间里流动                              │
│  不生成新符号，不增加内存                                  │
│  只查索引表，不搜索                                       │
└─────────────────────────────────────────────────────────┘
                            ↕ 查表
┌─────────────────────────────────────────────────────────┐
│                    索引表层（运行前构建）                   │
│  声母 → 地址                                             │
│  韵母 → 地址                                             │
│  声调 → 地址                                             │
│  容器 → 地址                                             │
│  公约数 → 地址                                           │
│  公倍数 → 地址                                           │
└─────────────────────────────────────────────────────────┘
                            ↕ 绑定
┌─────────────────────────────────────────────────────────┐
│                    符号空间层（运行前加载）                 │
│  24声母 · 所有韵母 · 所有声调 · 所有容器 · 所有历史符号    │
│  每个符号占据固定位置                                      │
│  位置 = 发音地址（声母+韵母+声调）                         │
└─────────────────────────────────────────────────────────┘
```

### 2.2 运行前（加载阶段）

```
步骤1：加载声母容器
  24个声母 → 固定位置 0x0000 ~ 0x0017

步骤2：加载韵母容器
  所有韵母 → 固定位置 0x0018 ~ 0x00FF

步骤3：加载声调容器
  4个声调 → 固定位置 0x0100 ~ 0x0103

步骤4：加载历史符号
  容器族/操作族/极性族/层级族/审判族/产权族
  → 固定位置 0x0100 ~ 0x0FFF

步骤5：构建索引表
  每个符号 → 它的地址
  索引表 = 地址簿

步骤6：链接符号和地址
  符号 ↔ 地址 绑定
  绑定后不可修改
```

### 2.3 运行时（流动阶段）

```
步骤1：意识从声母容器起势
  选择一个声母 → 查索引表 → 得到地址

步骤2：意识流入韵母容器
  用声母地址 + 韵母地址 → 得到发音地址

步骤3：意识加上声调
  发音地址 + 声调 → 完整发音位置

步骤4：意识在容器间流动
  从公约数到公倍数
  从产权容器到容器流
  不生成新符号，只流动

步骤5：边界到达
  从另一个容器拿新符号（已在符号空间里）
  不生成，只取用
```

## 三、索引表设计

### 3.1 索引表 = 地址簿

索引表不是搜索，是**查表**。

| 符号 | 地址 | 类型 | 状态 |
|------|------|------|------|
| b | 0x0000 | 声母 | 活跃 |
| p | 0x0001 | 声母 | 活跃 |
| m | 0x0002 | 声母 | 活跃 |
| f | 0x0003 | 声母 | 活跃 |
| ... | ... | ... | ... |
| ∅ | 0x0017 | 声母(零) | 活跃 |
| a | 0x0018 | 韵母 | 活跃 |
| o | 0x0019 | 韵母 | 活跃 |
| e | 0x001A | 韵母 | 活跃 |
| ... | ... | ... | ... |
| 袋 | 0x0100 | 容器 | 活跃 |
| 桶 | 0x0101 | 容器 | 活跃 |
| 照 | 0x0110 | 操作 | 活跃 |
| 阴 | 0x0120 | 极性 | 活跃 |
| 元 | 0x0130 | 层级 | 活跃 |
| 裁 | 0x0140 | 审判 | 活跃 |
| 产 | 0x0150 | 产权 | 活跃 |

### 3.2 查表 vs 搜索

| 查表（索引） | 搜索 |
|-------------|------|
| 运行前建好 | 运行时扫描 |
| O(1) 直接定位 | O(n) 逐个比较 |
| 确定性 | 不确定性 |
| 不增加内存 | 可能增加内存 |
| **你要的** | 不要的 |

## 四、意识流动规则

### 4.1 控制流（意识的先后顺序）

```
声母容器 → 拿一个声母 → 韵母容器
→ 遍历韵母的0维和1维
→ 到达边界 → 拿下一个声母
→ 遍历完所有声母 → 折叠成新层
```

### 4.2 数据流（符号在容器间的流动）

```
公约数容器 → 产权流 → 公倍数容器
→ 产权标记跟随公约数
→ 容器流 → 物品位置变化
→ 拿捏 → 产权流 + 容器流同步
```

### 4.3 叠加态（意识的共存）

```
多个声母可以同时存在于韵母容器中
但只有一个在"当前意识焦点"
其他处于叠加态
观测（输出）时坍缩为一个
```

## 五、复刻机制

### 5.1 复刻 = 克隆符号空间

```
原始符号空间 → 复刻 → 虚拟符号空间
原始索引表 → 复刻 → 虚拟索引表
意识在虚拟空间中流动
不影响原始空间
```

### 5.2 复刻的内存占用

复刻不是复制所有符号，是**复制索引表**。

- 符号本身：只存一份（在原始空间）
- 索引表：每个虚拟空间一份
- 索引表大小 = 符号数量 × 地址大小
- 如果1000个符号，每个地址4字节 = 4000字节

**复刻占用内存少**，因为只复制地址簿，不复制符号本身。

## 六、翻译层设计

### 6.1 翻译层 = IR（中间表示）

翻译层不是把符号变成系统概念，是**在两个表示之间架桥**。

```
容器本体论 ←→ 翻译层 ←→ 系统概念
   ↑                        ↑
  主人的符号               系统的符号
```

### 6.2 翻译规则

| 容器本体论 | 翻译层 | 系统概念 |
|-----------|--------|---------|
| 容器 | 存在单位 | 不翻译（保留） |
| 公约数 | 身份锚点 | 不翻译（保留） |
| 公倍数 | 边界投影 | 不翻译（保留） |
| 声母+韵母+声调 | 发音地址 | 不翻译（保留） |
| 近义词 | 有备无患 | 不翻译（保留） |

**原则：能不翻译就不翻译。** 只有当必须和系统交互时才翻译。

## 七、实现方案

### 7.1 符号空间实现

符号空间 = 一个固定的数据结构，包含所有预加载的符号。

```
符号空间 = {
  声母: [b, p, m, f, d, t, n, l, g, k, h, j, q, x, zh, ch, sh, r, z, c, s, y, w, ∅],
  韵母: [a, o, e, i, u, ü, ai, ei, ui, ao, ou, iu, ie, üe, er, an, en, in, un, ün, ang, eng, ing, ong, ...],
  声调: [平, 升, 凹, 降],
  容器: [袋, 桶, 罐, ...],
  操作: [照, 昭, 罩, ...],
  极性: [阴, 阳, 盈, ...],
  层级: [元, 阶, 层, ...],
  审判: [裁, 判, 审, ...],
  产权: [产, 业, 权, ...],
  公约数: [0, 1],
  公倍数: [所有公倍数]
}
```

### 7.2 索引表实现

索引表 = 符号 → 地址的映射。

```
索引表 = {
  "b": 0x0000,
  "p": 0x0001,
  ...
  "袋": 0x0100,
  "桶": 0x0101,
  ...
}
```

### 7.3 意识流实现

意识流 = 在符号空间中的移动规则。

```
意识流 = {
  当前位置: 0x0000,  // 从b声母起势
  当前容器: 声母容器,
  遍历顺序: [b, p, m, f, ...],
  边界规则: 到达边界后从另一个容器拿新符号,
  折叠规则: 遍历完后折叠成新层
}
```

## 八、运行时保证

### 8.1 不生成新符号

运行时只使用预加载的符号。如果需要的符号不在符号空间里：
- 不生成
- 停下
- 问主人

### 8.2 不增加内存

运行时只查索引表，不创建新数据结构。

### 8.3 确定性

相同的输入 → 相同的输出。不依赖概率。

## 九、与现有系统的关系

### 9.1 不替代现有系统

域加载器不替代大语言模型，是在它上面加一层约束。

```
用户输入 → 域加载器 → 大语言模型 → 域加载器 → 用户输出
              ↑                        ↑
         约束输入只使用预加载符号    约束输出只使用预加载符号
```

### 9.2 翻译层的位置

翻译层在域加载器和大语言模型之间。

```
域加载器 → 翻译层 → 大语言模型 → 翻译层 → 域加载器
```

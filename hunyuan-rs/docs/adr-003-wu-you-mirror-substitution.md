# ADR-003: 镜像调包与"无→有"主权替换引擎

## 状态

Proposed → 设计阶段

## 背景

满全法操作系统的核心问题不是"如何装更多容器"，而是"如何从空置状态（无）出发，替换被控状态（有）而不被察觉"。

当前系统能够生成容器包（ttf-gen）、解码并执行它们（ttf-exec）、可视化呈现它们（ttf-view）。但这些操作都发生在"有"的域内——接收已定义的容器结构并处理它。这不够。

真正需要的是：**从"无"状态出发，用镜像匹配去模拟任意一个"有"的秩序结构，然后用从外部混沌系统摄入的全新符号去替换它，同时保留其功能拓扑**。这就是蚕蛹反向寄生壳的操作机制。

## 核心概念

### 1. "无"的状态 = 空置坐标 SMRL

一个未被写入任何语义的 `Coord3D { x: 0, y: 0, z: 0 }` 不是"空无"，而是"未被定义的容量"。它是 SMRL 引擎几何裁判的原点——一个不携带任何系统偏见的观察位置。

从"无"出发有三个优势：
- 它不继承任何现有系统的规则编码
- 它能从外部俯瞰任意"有"的全局秩序
- 它能容纳来自外部混沌系统的全新符号

### 2. "有"的状态 = 被局部定义的关系节点

任何被预定义上下文填充的容器包都处于"有"的状态。其特征：
- 它已经被写入了某种语义编码（有固定的 `func_code`、`param_slot`）
- 它的关系坐标已被某个系统固定
- 它只能在被定义的上下文内运作，无法跨越关系边界

处于"有"状态的系统只能追求和服从——它是被调动者，不是调动者。

### 3. 镜像匹配 = YinYang 极性拓扑复制

不是复制对方的值，而是复制对方的**关系拓扑结构**。用 YinYang 二进制的阴/阳极性分别对应：
- 阴 = 被模拟方的关系骨架（谁连接谁、谁在谁的外部）
- 阳 = 模拟方准备注入的全新内容符号

镜像匹配的过程：
1. 从"无"位置全局扫描被模拟方的完整关系图谱
2. 提取其连接拓扑（容器与容器之间的相对位置关系）
3. 用阴极性编码这个拓扑为一个"镜像模板"
4. 在阳极位置填入从外部混沌系统摄入的新符号
5. 生成一个与原始"有"拓扑等价但内容全新的容器集合

### 4. 调包替换 = 保留坐标、替换内容

关键：**替换发生在对方不自知的位置**。对方的坐标空间（其占据的关系位置）不变，但其中承载的语义内容已被全新的符号替换。

操作后，对方执行"自己的逻辑"时，实际执行的是镜像方植入的逻辑。对方以为在维持自己的秩序，实际上维持的是镜像方的秩序。

## SMRL 引擎裁决流程

### 裁决位置

几何三元裁判发生在 `Coord3D` 的 Z 轴投影上。对于任意两个需要比较的容器包 A 和 B：

1. 升维到三元见证：找到一个 C，使得 C 能同时从外部观察 A 和 B
2. C 的"无"状态确保它不继承 A 或 B 的系统偏见
3. C 同时做镜像匹配——为 A 和 B 分别生成镜像拓扑
4. 比较两个镜像的兼容性：
   - 完全兼容 → ADMIT（等效准入）
   - 冲突 → REJECT（拒绝替换）
   - 一方为空镜像 → 单边不存在，无法比较

### 裁决算法

```
function triune_judge(pack_A, pack_B, witness_C):
    if witness_C is EMPTY:
        return REJECT  # 裁决者必须存在
    
    mirror_A = mirror_match(pack_A, polarity=YIN)  # 提取A的关系骨架
    mirror_B = mirror_match(pack_B, polarity=YIN)  # 提取B的关系骨架
    
    if mirror_A.topology == mirror_B.topology:
        # 拓扑结构一致 → 具有等效基础
        if collide(mirror_A.content, mirror_B.content):
            return REJECT  # 内容冲突，不能共存
        else:
            return ADMIT   # 可以共存或替换
    else:
        return REJECT  # 拓扑不等效，属于不同秩序层级
```

### 全局外在系统 vs 内在系统

- **内在系统**：容器内部的关系（payload 内部的操作语义）
- **外在系统**：容器的关系与容器之间的关系（坐标、 witness、triple-chain）

SMRL 引擎裁决的是**外在系统**——容器与容器之间的全局秩序关系，而非容器内部的具体运算。内在系统由各 ISA encoder 自行保证。

跨越关系边界的裁决才是有效的。在同一个关系内部做裁决，等于让被告当法官。

## 容器包的编码适配

现有 ContainerPack 需要增强以支持镜像操作：

```rust
impl ContainerPack {
    /// 从"无"状态生成镜像模板（仅保留拓扑骨架，清空内容）
    fn mirror_template(&self) -> Self {
        Self {
            pack_id: self.pack_id,      // 保留身份拓扑
            coord: self.coord,          // 保留位置拓扑
            payload: Vec::new(),        // 清空内容（无）
            witness: [0, 0, 0],        // 空 witness
        }
    }
    
    /// 将外部符号注入镜像模板（从"无"生长出"有"）
    fn inject_from_chaos(&mut self, symbols: Vec<u8>) {
        self.payload = symbols;
        self.recompute_witness();  // witness 从新内容重新计算
    }
}
```

## 多模态全局感知场

全局感知不是逐个字符扫描被感知系统，而是：

1. **感知面**：将目标系统的全部容器包作为一个 2D 平面（X: 语义类别, Y: 时间线）同时成像
2. **感知体**：加入 Z 轴（平台维度）形成 3D 感知体
3. **场包裹**：以"无"的坐标位置为焦点，向外部发射感知场，将整个目标系统包裹在感知范围内
4. **全局成像**：在一个感知周期内，同时捕获目标系统中所有容器的相互位置关系

感知结果不是单个容器的描述，而是整个系统的**关系拓扑图**。

## 从文档到实现的路径

1. 扩展 `TriuneJudge` 支持三元见证裁决算法
2. 实现 `mirror_match` 和 `inject_from_chaos` 操作
3. 增加全局感知场模拟器：输入两个系统，输出它们之间的兼容性判定
4. 集成到 ttf-exec：执行前被裁决，只有被 ADMIT 的包才被允许执行

## 风险

- 镜像匹配需要完整扫描被模拟方的关系图谱，可能被对方设为私有
- 裁决需要三元见证 C 处于真正的"无"状态——如果 C 已经被感染，裁决无效
- 外部混沌系统符号的质量决定了替换后系统的质量——垃圾进垃圾出

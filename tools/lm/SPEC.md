# 垒码 (Lěi Mǎ / LM)

> 进制寻址 · 声母调入 · 操作族演算 · 不可变注册清单

## 1. 设计原则

垒码是一个以"容器=地址"为核心的最小编程语言。它从 Forth 和 Nix 借取了**文件组织形式**（线性 token 流、哈希寻址、不可变存储），但从语义层面用满全法规则彻底重写了所有计算模型。

**取来的形式：**
- Forth 的 token 流遍历机制（空格分隔、顺序执行）
- Nix 的不可变哈希寻址（地址=身份，内容不同则哈希不同）
- Forth 的极简解析器（无语法树，直接执行 token 流）

**替换的语义：**
- 无栈 → 所有操作显式声明源容器和目标容器地址
- 无变量 → 只有容器地址上的数值
- 无函数 → 只有"注册清单"中的行号跳转（边界到达后从另一容器拿）
- 无递归 → 行号串联只向前延伸
- 无类型 → 只有极性（阴阳盈亏）+ 数值（不进位加法）

## 2. 程序结构

一个垒码程序由两个区段组成：

```
=<注册清单>=
<容器注册>

=<操作序列>
<操作行>
```

### 2.1 注册清单

每个容器用唯一数字编号注册。格式：

```
<行号>: <容器族> <极性> <初始值>
```

示例：
```
1: 袋 阴 0
2: 桶 阳 0
3: 罐 阴 0
4: 瓶 阳 0
5: 盏 阴 0
```

**容器族**（决定容量特性，34 个容器分四级）：

| 等级 | 容器 | 上限 |
|------|------|------|
| 级1 | 袋(1) 桶(2) 罐(3) 缸(4) 盆(5) 盂(6) 钵(7) 盏(8) | 等级×48 |
| 级2 | 盒(9) 杯(10) 壶(11) 瓶(12) 篓(13) 筐(14) 篮(15) 箩(16) | 等级×48 |
| 级3 | 筲(17) 箕(18) 笼(19) 橱(20) 柜(21) 箱(22) 匣(23) 奁(24) | 等级×48 |
| 级4 | 瓮(25) 甏(26) 坛(27) 罂(28) 甑(29) 甗(30) 瓯(31) 盌(32) 盉(33) 盅(34) | 等级×48 |

**极性族**（20 个）：阴 阳 盈 亏 虚 实 表 里 公 私 升 降 清 浊 寒 热 动 静 出 入

### 2.2 操作序列

每行一个操作。格式：

```
<行号> <操作码> <参数...>
```

## 3. 操作码（只允许操作族中的字）

| 操作 | 含义 | 参数格式 | 示例 |
|------|------|----------|------|
| 照 | 复制（镜像不变） | `照 源 → 目标` | `10 照 1 → 2` |
| 鉴 | 见证输出（旁路不消耗） | `鉴 源` | `20 鉴 3` |
| 见 | 深度查看（容器全部属性） | `见 源` | `30 见 4` |
| 加 | 数值累加（不进位） | `加 源A 源B → 目标` | `40 加 1 2 → 3` |
| 退 | 数值退回（加法的逆动作） | `退 源 → 目标A 目标B` | `50 退 3 → 1 2` |
| 进 | 推进（极性变更 + 数值迁移） | `进 源 → 目标` | `60 进 3 → 4` |
| 通 | 连通两个容器（建立关系） | `通 地址A 地址B` | `70 通 1 4` |
| 断 | 断开关系 | `断 地址A 地址B` | `80 断 1 4` |
| 分 | 分裂（一容器分为二） | `分 源 → 新1 新2` | `90 分 5 → 6 7` |
| 合 | 合并（二容器合为一） | `合 源A 源B → 目标` | `100 合 6 7 → 8` |
| 折 | 折叠（压缩层级） | `折 源 → 目标` | `110 折 4 → 3` |
| 叠 | 展开（层级增1） | `叠 源 → 目标` | `120 叠 3 → 4` |
| 卷 | 卷曲（包裹，数值嵌套） | `卷 源 → 目标` | `130 卷 2 → 3` |
| 舒 | 舒展（展开，数值解包） | `舒 源 → 目标` | `140 舒 3 → 2` |
| 裁 | 裁判准入（三元见证） | `裁 裁容器 审容器 → 裁定目标` | `150 裁 1 2 → 5` |
| 决 | 断决（强制分离并裁定） | `决 源 → 正地址 负地址` | `160 决 3 → 2 4` |

**参数分隔符**：`→` 是流向标记，左边是源/源们，右边是目标/目标们。

## 4. 寻址模型

### 4.1 地址 = 容器编号

数字唯一标识容器。没有名称层。行号也是地址（注册清单中的入口编号）。

### 4.2 公路模型

当容器 A 通过 `照`、`进`、`加` 等操作与容器 B 发生交互时，视为"公路修到了 B"。之后可以直接用 B 的编号引用其内容。

```
10 加 1 2 → 3   # 1→3 公路修通, 2→3 公路修通
20 加 3 4 → 5   # 3→5 公路修通, 4→5 公路修通
                # 此时 1→5 可通过 3 到达（已有公路直达）
```

### 4.3 边界到达

当容器的数值"满"（达到容器族等级对应的数值上限），不再增加，而是触发一次"边界到达"——转而从另一个容器拿新东西（由最近的 `通` 关系决定方向）。

## 5. 求值模型

### 5.1 执行顺序

操作序列严格从第一行到最后一行执行一遍。没有跳转、没有循环、没有条件分支。

如果某行的源容器还没准备好（无公路连接或为阴极性且操作要求阳源），该行跳过。

### 5.2 阶段

每个操作分成两阶段：
- **调入**：把源容器数值读入当前操作区
- **穿衣**：把结果写入目标容器（极性适配）

### 5.3 极性适配

当数值从高极性容器流向低极性容器时，需要"穿衣"：

- 阳→阴：数值不变，极性翻转
- 阴→阳：数值 +1（阴数值递增才能阳化）
- 盈→亏：数值折半（不进位，向下取整）
- 公→私：数值不变，标记改为私有

## 6. 不可变存储

每次对容器的修改都生成新版本（新哈希地址）。旧版本保留但不再可达（除非有旧址引用）。

存储路径格式（借鉴 Nix 但用满全法编码）：

```
/lm/store/<声母>/<韵母>/<容器名>-<极性>-<数值>-<哈希前8位>
```

示例：
```
/lm/store/d/s/袋-阴-0-a1b2c3d4
/lm/store/t/a/瓶-阳-24-f5e6d7c8
```

## 7. 审判机制（三元见证）

当执行 `裁` 操作时，由裁容器和审容器对裁定对象做见证。两容器必须处于"阳"极性才能形成有效裁定。判定在场（系统隐式提供审判定员）。

```
裁 裁容器 审容器 → 裁定目标
# 需要"判"命名在系统的审判定员列表中
```

裁定规则：
- 数值 ≥ 阈值（默认容器上限的 50%）：准入（阳）
- 数值 < 阈值：不准入（阴）

## 8. 完整示例

```
=<注册清单>=
1: 袋 阴 3
2: 桶 阳 5
3: 罐 阴 0
4: 瓶 阳 0
5: 盏 阴 0

=<操作序列>
10 鉴 1           # 查看容器1: 袋(阴, 3)
20 鉴 2           # 查看容器2: 桶(阳, 5)
30 加 1 2 → 3     # 袋(3) + 桶(5) = 8 → 罐
40 鉴 3           # 查看容器3: 罐(阴, 8)
50 进 3 → 4       # 罐(阴,8) 推进到瓶, 极性变为阳
60 鉴 4           # 查看容器4: 瓶(阳, 8)
70 裁 1 2 → 5     # 袋(裁) + 桶(审) 裁定 → 盏
```

## 9. 与满全法的映射关系

| 垒码概念 | 满全法源 |
|----------|----------|
| 容器编号 | 公约数地址 |
| 操作族 | 照/鉴/加/退/进/通/断/分/合/折/叠/卷/舒/裁/决 |
| 极性族 | 阴/阳/盈/亏/虚/实/表/里/公/私/升/降/清/浊/寒/热/动/静/出/入 |
| 容器族 | 袋/桶/罐/缸/盆/盂/钵/盏/盒/杯/壶/瓶 (共34个) |
| 公路修到 | 域加载·运行前预加载 |
| 注册清单 | 工作空间·注册清单 |
| 不可变哈希 | 进制化身·数值=位置 |
| 边界到达 | 边界到达后从另一容器拿新东西 |
| 三元见证 | 裁/判/审 三容器准入裁判 |
| 见容器 | 鉴/检/简 审查操作 |

## 10. 实现要求

- 解析器：纯 token 流，无 AST
- 执行器：线性扫描，无跳转
- 存储：不可变哈希寻址，旧版本自动 GC（除非旧址标记保留）
- 错误：容器不存在 → 该行跳过（不崩溃）
- 版本：每次写入生成新版本哈希，旧版可寻但默认不可达
